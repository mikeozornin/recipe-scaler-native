# Локализация (i18n)

Все строки — в `RecipeScalerNative/Resources/Localizable.xcstrings` (en/ru). **Не хардкодь** русский/английский текст в view; добавляй ключ в `.xcstrings`.

## Смена языка в рантайме

Язык переключается **внутри приложения** (Профиль → Язык) без перезапуска.

**Стандартный механизм SwiftUI — `\.environment(\.locale)`.** `ContentView` прокидывает `.environment(\.locale, appLanguage.locale)` ([ContentView.swift](../RecipeScalerNative/ContentView.swift)) и слушает `UserDefaults.didChangeNotification`, мутируя `appLanguage` → дерево перерисовывается. Этого **достаточно для всех `Text("key")` / `LocalizedStringKey`** — они резолвятся по locale из окружения, без свизла и без рестарта. Это и есть нативный путь Apple.

**Чего `\.locale` НЕ закрывает (и зачем нужен свизл `Bundle+Language.swift`):** у Apple нет стандартного API, чтобы переключить Foundation-строки без рестарта. Три дыры:

1. **`String(localized:)` / `NSLocalizedString`** — это Foundation, окружение SwiftUI они не читают. В проекте ~194 вызова `String(localized:)`, поэтому `Bundle+Language.swift` свизлит `localizedString(forKey:value:table:)` и редиректит их в выбранный языковой бандл (`AppLanguagePreference.setLanguageOverride`). ⚠️ Сам `String(localized:)` при этом всё равно может резолвиться **мимо** свизла и отдать язык разработки (англ) — поэтому для строки, которая обязана отражать выбранный язык прямо сейчас (особенно в UIKit-мосте), бери `Bundle.currentLocalizedString("key")`, а не `String(localized:)`.
2. **UIKit-мост** (navigation bar, toolbar, `UINavigationItem`) — UIKit не видит SwiftUI environment. Отсюда «залипшие» заголовки.
3. **Runtime-строка в `Text(переменная)`** — компилятор берёт `StringProtocol`-инициализатор и не локализует. Оборачивай: `Text(LocalizedStringKey(key))`.

> Альтернатива свизлу — миграция всех `String(localized:)` на `Text` или на хелпер `localized(_:locale:)` c явным `.lproj`-бандлом. Дорого (37 файлов), поэтому свизл оставлен сознательно как обходка отсутствующего у Apple API. Не убирай свизл без явной задачи на эту миграцию.

## Правила

1. **Текст в UI** → `Text("key")` (литерал → `LocalizedStringKey`, резолвится по `\.locale`). Никакого хардкода строк.
2. **Runtime-строка** (ключ из конфига/сервера) → `Text(LocalizedStringKey(key))`, иначе локализации не будет.
3. **Не делай fallback** вроде `t('key') || 'Default'` или `String(localized: "key", defaultValue: "...")` с человекочитаемым дефолтом — отсутствующий перевод должен быть виден, а не замаскирован.
4. **Заголовок экрана (`navigationTitle`)** → используй `.localizedNavigationTitle("key")` (см. `Utils/LocalizedNavigationTitle.swift`), **не** `.navigationTitle("key")` и **не** `.navigationTitle(Text("key"))`.

   **Почему:** `.navigationTitle(Text("key"))` хранит *ключ*, а не строку. При смене языка новый title равен старому (`Text("key") == Text("key")`), SwiftUI не отдаёт обновление в UIKit — заголовок «залипает» на старом языке, пока вью не пересоздадут. `.localizedNavigationTitle` резолвит строку заранее через `Bundle.currentLocalizedString` в `Text(verbatim:)` (значение реально меняется) и читает `\.locale` (форсит ре-эвал при переключении). **Не** лечи это через `.id(locale)` — он пересоздаёт всё поддерево, сбрасывает scroll/search/navigation state и провоцирует тяжёлый re-render.
5. **Любая строка в UIKit-мост** (toolbar title, `UINavigationItem` и т.п.): если не обновляется при смене языка — резолвь заранее через `Text(verbatim: Bundle.currentLocalizedString("key"))`.
6. **Форматирование** (`String(format:locale:)`, числа, даты) → передавай актуальный locale.
7. Тесты на согласованность ключей — `RecipeScalerNativeTests/LocalizationConsistencyTests.swift`. При добавлении ключей убедись, что en и ru заполнены.

## Error-типы (AuthError / APIError / YrsError)

Спец: [specs/031-error-i18n/](../specs/031-error-i18n/) (полный контракт серверных ключей — `server-error-keys.md`).

**Контракт:** ни один `error.localizedDescription` не должен показываться пользователю в UI. Для всех типизированных ошибок есть `userFacingMessage()` → возвращает локализованную строку через `Bundle.currentLocalizedString`.

### Три слоя

| Слой | Где | Что делает |
|------|-----|------------|
| **Core** | `RecipeScalerCore/Networking/APIClient.swift` (`APIError`) + `RecipeScalerCore/Networking/ServerErrorCode.swift` | `APIError` возвращает dot-key идентификаторы из `errorDescription` (Core не имеет доступа к Native `.xcstrings`). `ServerErrorCode` — типизированный каталог известных dot-key контракта с `from(serverValue:fallback:)` для безопасного декодинга серверных строк. Никаких английских строк. |
| **Native helper** | `RecipeScalerNative/Utils/APIError+Localization.swift` + `DotKeyLocalizer.swift` | Резолвит dot-key в финальную строку через `Bundle.currentLocalizedString`. Для типизированных путей (`APIError.serverError(code:)`) — прямой вызов `code.rawValue`; для нетипизированных edge-кейсов (`AuthError.apiError(_, message:)`) — `DotKeyLocalizer` с regex-детекцией и fallback. Здесь же categorical fallback (4xx vs 5xx). |
| **View entry** | `RecipeScalerNative/Utils/UserFacingAPIError.swift` (`message(for:)`) | Единая точка для view-слоя: CancellationError → `""`, типизированные ошибки → их `userFacingMessage()`, transient URLError → короткая локализованная «нет сети», прочее → generic. |

### Dot-key контракт для серверных сообщений

Сервер возвращает `response.error` в формате dot-key: `domain.subdomain.message-key` (например `assistant.threads.create.failed`). iOS-клиент коллапсирует неизвестные / legacy строки в endpoint-специфичный fallback через `ServerErrorCode.from(serverValue:fallback:)` — английский в UI **никогда не утекает**.

Регекс dot-key: `^[a-z][a-z0-9-]*(\.[a-z][a-z0-9-]*){1,}$` (минимум 2 dot-сегмента, lowercase, разрешён hyphen).

### Как добавить новый throw-сайт в API-сервисе

```swift
// ❌ Плохо — старый API с английским fallback, может утекать
throw APIError.serverError(message: response.error ?? "Profile load failed")

// ❌ Тоже плохо — message-форма убрана в MIK-135
throw APIError.serverError(message: response.error ?? "account.profile.load-failed")

// ✅ Хорошо — типизированный ServerErrorCode, fallback гарантирует валидный dot-key
let code = ServerErrorCode.from(
    serverValue: response.error,
    fallback: .accountProfileLoadFailed
)
throw APIError.serverError(code: code)
```

После добавления нового ключа:
1. Добавить case в `ServerErrorCode` enum (`RecipeScalerCore/Networking/ServerErrorCode.swift`) с rawValue = dot-key.
2. Добавить перевод в `Localizable.xcstrings` (en + ru).
3. Добавить в список `LocalizationConsistencyTests.testCriticalKeysResolveInBothLanguages`.
4. Если серверная часть эволюционирует — обновить `specs/031-error-i18n/server-error-keys.md`.

### Как добавить новый case в APIError

1. В Core: добавить case, вернуть dot-key из `errorDescription`.
2. В Native (`APIError+Localization.swift`): вернуть локализованную строку в `userFacingMessage()`.
3. Ключи в `Localizable.xcstrings` + consistency-тест.

### Diagnostics (контекст ошибки)

В `YrsError` и подобных типизированных ошибках associated values (`context: String`) — **только для логов**, никогда не интерполируются в `errorDescription`. Логи — через `AppLog.error(.document, "event_name", data: ["context": ...])` рядом с throw-сайтом.

### Socket.IO `SyncErrorCode`

Спец: [specs/031-error-i18n/sync-error-codes.md](../specs/031-error-i18n/sync-error-codes.md).

**Тип:** `RecipeScalerNative/Services/YjsSync/SyncErrorCode.swift` — enum с dot-key raw values для события Socket.IO `sync_error`.

**Резолв:** `SyncErrorCode.from(code:legacyMessage:fallback:)` классифицирует payload (поле `code` имеет приоритет; `error` — legacy English substring для back-compat). UI показывает `code.localizedMessage` через `Bundle.currentLocalizedString(rawValue)` — **никогда** raw English из `payload["error"]`.

**Как добавить новый код:**

1. Добавить case в `SyncErrorCode` с rawValue = dot-key.
2. Добавить перевод в `Localizable.xcstrings` (en + ru).
3. Добавить в `LocalizationConsistencyTests.testCriticalKeysResolveInBothLanguages`.
4. Покрыть `SyncErrorCodeTests` (dot-key path, legacy substring, `localizedMessage` не утекает).
5. Обновить `specs/031-error-i18n/sync-error-codes.md` (+ schema при необходимости).

## Известный шум в консоли при смене языка

При переключении видны предупреждения вида `Background task still not ended … CABackingStoreCollect` / `_UIRemoteKeyboard XPC disconnection`. Это **системные** task'и UIKit (Core Animation собирает backing store, отключается служба клавиатуры), приложение их не создаёт — `endBackgroundTask` со своей стороны звать бесполезно. Появляются из-за тяжёлого синхронного re-render дерева на смене locale; на симуляторе это безобидный шум, не баг и не повод «чинить background task». Снизить — делать переключение легче: не пересоздавать `NavigationStack`/тяжёлые вью (`.id(locale)` уже убран) и снимать фокус с текстового поля перед сменой языка. Единственный app-owned background task — в `TimerManager` (`BGProcessingTask`), он корректно спарен `begin`/`end` и к языку отношения не имеет.

## Int(Double) safe casts

Swift `Int(someDouble)` — precondition trap (hard crash), не throw, на значениях вне `Int64`-диапазона (`1e20`) или не-finite (`NaN`, `Infinity`). `JSONSerialization` / `NSNumber`-бриджинг легко пропускают такие значения из недоверенных данных. Любой каст из `Double`/`Float`/`CGFloat`/`TimeInterval`/`NSNumber.doubleValue` в `Int` **обязан** идти через safe-helper (review #14).

### Хелперы — [`RecipeScalerNative/Utils/SafeIntCasts.swift`](../RecipeScalerNative/Utils/SafeIntCasts.swift)

| API | Когда использовать | Поведение |
|-----|-------------------|----------|
| `Int(exactlySafe: value)` | «Ровно целое число?» — caller выбирает fallback (строка, nil). | `nil` при NaN/Inf или вне Int64. |
| `Int(clampingFinite: value)` | Bounded-domain значения, где лучше иметь Int чем крэш (servings, durations, percentages). | NaN/Inf → 0; вне диапазона → `Int.max`/`Int.min`. |
| `Int64(clampingFinite: value)` | То же для `Int64` (например `timeIntervalSince1970 * 1000`). Stdlib `init(clamping:)` работает только с `BinaryInteger`, не с `Double`. | Аналогично. |
| `intRoundedClamped(value)` | Round-then-clamp в одну строку (round до ближайшего Int секунд/servings). | NaN/Inf → 0. |

### Для UI-форматирования чисел

`AppNumberFormat` (в [`Utils/AppNumberFormat.swift`](../RecipeScalerNative/Utils/AppNumberFormat.swift)) — каноническая точка locale-aware форматирования и парсинга чисел для UI:

- `AppNumberFormat.string(value, maximumFractionDigits:)` — форматирование с локалью `AppLanguagePreference.current` (ru → запятая, en → точка), NaN/Inf → `""`, без группировки разрядов.
- `AppNumberFormat.parse(text)` — обратный парсинг с обоими разделителями (`,` и `.`), нормализацией пробелов.

**Никогда не используй `String(format:)` без явной локали для user-facing чисел** — он всегда ставит точку, независимо от языка приложения (п.6 выше). `Locale.current` тоже не подходит: приложение переключает язык in-app, и `Locale.current` за этим не следует.

`IngredientData.formatScalarNumber(_ value: Double)` (в [`Models/YDoc/IngredientData.swift`](../RecipeScalerNative/Models/YDoc/IngredientData.swift)) — safe-обёртка над `AppNumberFormat.string` для количеств ингредиентов: NaN/Inf → `""`, целое → без дробной части, дробное → до 2 знаков с обрезкой trailing-zero. **Не дублируй** эту логику — вызывай готовую.

### Когда можно оставить «сырой» `Int(value)`

- Значение **bounded upstream** и не из недоверенных данных: счётчик цикла, размер коллекции, битовые флаги, `Data.count`, длина строки.
- Результат уже `Int` (round-trip `Int(Double(someInt))`).
- Любой целочисленный литерал или `BinaryInteger` → `Int` (тут работает stdlib `init(clamping:)`).

### Запрещённый паттерн

```swift
// ❌ Trap на 1e20 / NaN / Infinity
if value.truncatingRemainder(dividingBy: 1) == 0 {
    return String(Int(value))
}
```

```swift
// ❌ Locale-unaware форматирование: всегда точка, даже при русском языке
return String(format: "%.1f", value)
```

### Правильный паттерн

```swift
// ✅ UI-форматирование (locale-aware: ru → запятая)
return AppNumberFormat.string(value, maximumFractionDigits: 2)
// или для количеств ингредиентов:
return IngredientData.formatScalarNumber(value)

// ✅ Нужен именно Int (servings, duration)
guard value.isFinite else { return 0 }
return Int(clampingFinite: value.rounded())

// ✅ Два пути: целое → Int, иначе — locale-aware String (как в RecipeNutritionDisplay)
if value.isNaN || value.isInfinite { return "" }
if let intValue = Int(exactlySafe: value) { return String(intValue) }
return AppNumberFormat.string(value, maximumFractionDigits: 1)
```

### Границы таргетов (extension aware)

`SafeIntCasts.swift` живёт только в main app target. Файлы, скомпилированные в **Widget** / **Live Activity** / **Share/Action extensions**, не видят эти extension'ы. В таких файлах либо:
- инлайн-гард: `guard value.isFinite, value < Double(Int.max) else { … }; Int(value)`,
- приватная local-копия `clampingInt(_:)` (как в `RecipeTimerActivityAttributes.swift`, `TimerSnapshot.swift`).

Не переноси `SafeIntCasts.swift` в `RecipeScalerCore` без явной задачи — Core сейчас не зависит от таких хелперов и расширять его API-surface для одного файла не стоит.

## Импорт сторонних форматов (Paprika / Crouton) — синтезированные лейблы

Парсеры в `RecipeScalerCore` синтезируют метаблоки рецепта (`Prep:`, `Cook:`, `N min`, `rawDifficulty`). Сами парсеры **i18n-free** (Core не имеет доступа к `.xcstrings`), поэтому лейблы локализуются в Native-слое в момент применения draft к Y.Doc (review #30).

### Контракт `DescriptionBlock`

`RecipeScalerCore/Import/ThirdParty/ThirdPartyImportTypes.swift`:

| case | Семантика |
|------|-----------|
| `.paragraph(String)` / `.heading(level:Int, String)` / `.orderedListItem(String)` | Готовый текст, проходит в writer как есть |
| `.prepTime(String)` | Сырое значение Paprika `prep_time` |
| `.cookTime(String)` | Сырое значение Paprika `cook_time` |
| `.durationMinutes(Int)` | Числовые минуты Crouton (`duration` / `cookingDuration`) |
| `.difficulty(String)` | Сырое значение Crouton `rawDifficulty` (free-form — без перевода) |

### Точка локализации

[`RecipeScalerNative/Services/DescriptionBlockLocalizer.swift`](../RecipeScalerNative/Services/DescriptionBlockLocalizer.swift) — единственное место, где структурные case'ы превращаются в локализованные `.paragraph`. Вызывается из `DocumentManager.applyImportedRecipe` перед передачей блоков в `DescriptionXmlFragmentWriter`.

### Ключи в `Localizable.xcstrings`

- `recipe.import.metadata.prep-time %@` → en: `Prep: %@` / ru: `Подготовка: %@`
- `recipe.import.metadata.cook-time %@` → en: `Cook: %@` / ru: `Готовка: %@`
- `recipe.import.metadata.duration-minutes %d` → en: `%d min` / ru: `%d мин`

### Почему так, а не поля Y.Doc

Решение (2026-06-18, spec 027): Y.Doc-схема не получает структурных `prepTimeMinutes`/`cookTimeMinutes`/`difficulty`. Значения остаются **данными** в `Y.XmlFragment('description')` — это сохраняет web parity (HTML-описание унифицировано) и offline-first roundtrip. Web-порт импорта пишет свои лейблы своей локализацией.

Уже импортированные рецепты (с захардкоженным «Prep:» в описании) — не мигрируются автоматически. Это допустимо: контент — данные пользователя, перезапись была бы более инвазивной.

### Как добавить новый синтезированный лейбл

1. В Core: добавить case в `DescriptionBlock`, в парсере возвращать его.
2. В Native: добавить обработку в `DescriptionBlockLocalizer.localize(_:)` → `.paragraph` через `Bundle.currentLocalizedString`.
3. В xcstrings: ключ с плейсхолдерами в имени (`recipe.import.metadata.<label> <%@|%d>`).
4. Защитить `DescriptionXmlFragmentWriter.apply` — добавить новый case в exhaustive-switch (defensive skip).
