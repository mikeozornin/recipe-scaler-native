# Code Review: 077-ios-release-notes

## Summary

Spec 077 (in-app release notes) is a coherent slice: composition-root store, seed/`lastViewed` invariants, banner slots matching 061, sheet + Profile archive, i18n chrome, and unit tests that cover the seed/banner/expand-before-write table.

Reviewed: **Business Logic**, **Architecture**, **Security**, **Standards**. Skipped **Performance** — static catalog, no network, no hot-path queries.

Risk is **low for the mechanism**, **high if this branch ships the sample cooking-mode note**. Security: nothing found. Business logic of the store matches the spec; reviewers did not report defects in seed, dismiss, unread-before-write, empty catalog, or logout persistence.

## Findings (sorted by priority)

### High

1. **[Standards]** Sample catalog note will ship in the 077 binary
   - Impact: `IOSReleaseNotesCatalog.notes` is not `[]`. First launch seeds `lastViewed = 2` (no banner), but the Profile row **«Что изменилось в приложении»** appears and the archive is real copy. That breaks the empty-catalog / mechanism-introducing-build rule (T005 / FR-014 / STOP: no catalog write without human «да, в каталог»). A later empty catalog cannot use sentinel `0` for users already seeded to 2.
   - Recommendation: Reset `notes` to `[]` on the shipping 077 cut. Keep the cooking-mode copy only as a local preview (or behind DEBUG). Put a note in the catalog only after an explicit catalog approval from `prepare-ios-release`.

### Medium

2. **[Architecture]** Store contract still documents `screenshotCapture` on `init`
   - Impact: `contracts/store.md` specifies `init(defaults:catalog:screenshotCapture:)`. The store only takes `defaults` and `catalog`. Hide lives in `ReleaseNotesChrome` via `DebugLaunchOptions.screenshotCapture`, same as `SystemBannerChrome`. Aligning code to the stale contract would leak a UI/launch flag into domain state.
   - Recommendation: Drop `screenshotCapture` from the store contract. Document the 061 DEBUG chrome path. Do not add `test_screenshot_hides_banner` unless the flag is injected for tests.

## Recommendation

**Changes requested** before merge-to-release: empty the catalog (or explicitly accept shipping this DRAFT note). Optionally sync `contracts/store.md` with the chrome screenshot gate.

The rest of the implementation (AppContainer injection, logout isolation, tests, localization keys, banner slots on list/empty/loading) is in good shape.
