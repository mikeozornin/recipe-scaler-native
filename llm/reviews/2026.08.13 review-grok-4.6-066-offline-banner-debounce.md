# Code Review: 066-offline-banner-debounce

## Summary

Reviewed uncommitted work on `066-offline-banner-debounce` against `specs/066-offline-banner-debounce/spec.md` (iteration 3: signal is `!connectionState.isConnected`). Areas: **Business Logic**, **Architecture / DI**, **Standards**. Skipped: **Security** (no input/auth/secrets), **Performance** (one MainActor `Task.sleep`).

Gate FSM, composition-root DI, and in-foreground unit tests are solid. The primary user story (no flash on unlock) still fails for a typical lock longer than 3s, because background disconnect arms the same timer that is supposed to absorb only the *foreground* reconnect flash. Spec/docs still describe dropped signals (`networkReachable`, `isHardOffline`), which would invite a wrong “fix.”

## Findings (sorted by priority)

### Critical

1. **[Business Logic]** Background disconnect arms the gate; unlock after >3s still flashes banners — `AppShellView.swift:256`, `OfflineBannerGate.swift:43`, `YjsSyncService.swift:1700`
   - Flow: lock → `handleEnteredBackground()` → `.disconnected` (`app_background`) → `offlineGate.update(true)` → `Task.sleep(3s)` can finish while backgrounded (or expire immediately on resume) → `isVisible = true`. On unlock the FSM is still `.disconnected`/`.connecting`; `.connecting` is `!isConnected`, so FR-005 makes `update(true)` a no-op. Banners stay until `.connected`.
   - That is US1 / SC-001. Debounce only helps if the app was backgrounded for <3s. Spec Edge Cases call showing after >3s in background «корректно»; that contradicts US1 (no duration qualifier) and FR-007’s rationale that 3s absorbs the *foreground* reconnect flash.
   - Impact: Common phone lock >3s → brief offline banners on unlock even when the network is fine.
   - Recommendation: Do not count background time. Suppress while `scenePhase != .active`, or reset the gate on background and re-arm on `.active` with a fresh 3s window so reconnect can cancel before show. Keep `!isConnected` (do not disarm on `.connecting` — that would break US2). Add a test: background-arm → resume → reconnect within threshold → never visible.

### High

2. **[Business Logic]** No test for the unlock / background path — `OfflineBannerGateTests.swift`
   - Suite only drives `update(true/false)` in-process. `testShortDipDoesNotShow` covers reconnect *before* the threshold, not “timer already fired while backgrounded, then `.connecting` then `.connected`.”
   - Impact: Finding 1 cannot fail CI.
   - Recommendation: After the US1 fix, assert the gate stays hidden across simulated background-expire + foreground reconnect. Do not encode “banner stays visible through `.connecting` after a completed arm” as the desired contract unless US1 is explicitly dropped.

3. **[Standards]** Spec Key entities / Downstream consumers still say `networkReachable` drives the gate — `specs/066-offline-banner-debounce/spec.md` (~162, ~168, ~170)
   - FR-007, Assumptions, and `AppShellView` use `!connectionState.isConnected`. Zero Swift call sites of `.networkReachable`.
   - Impact: A later change will re-subscribe to NWPathMonitor, which device evidence already showed stays `.satisfied` in airplane mode.
   - Recommendation: Align those sections with FR-007; keep FR-001 only if the unused API is intentionally retained.

4. **[Standards]** Stale doc-comment on `YjsSyncService.networkReachable` — `YjsSyncService.swift:1667`
   - Comment still claims the gate uses this instead of `connectionState`. Runtime wiring does not.
   - Impact: Same wrong rewiring as (3), next to the public API.
   - Recommendation: Document as unused projection (FR-001) or remove the property (this review is the audit FR-001 asked for).

5. **[Standards]** `update(isHardOffline:)` / US3 AS1 contradict the actual signal — `OfflineBannerGate.swift:43`, spec US3 AS1, Edge Cases
   - Callers pass `!isConnected` (includes `.connecting` / `.reconnecting`). US3 AS1 says hide on those states; Edge Cases still mention `connectionState.isHardOffline` (API gone). Code hides only on `.connected`, which is required for US2.
   - Impact: A “fix” that disarms on `.connecting` would break airplane-mode arming.
   - Recommendation: Rename the parameter (`isNotConnected` / `shouldArm`). Rewrite US3 AS1 to hide only on `.connected`. Fix US1 via scenePhase (finding 1), not via connecting-disarm.

### Medium

   - Impact: Extra API that documents a rejected design.
   - Recommendation: Remove in this PR, or make it internal and fix the comment. Do not leave a public alias that claims the gate uses it.

7. **[Architecture]** `AccountView.#Preview` does not inject `OfflineBannerGate` — `AccountView.swift:22`

8. **[Standards]** `AGENTS.md` SPECKIT block still points at `specs/065-share-feedback/plan.md`
   - `.specify/feature.json` already points at 066; 066 has `spec.md` only (no `plan.md`).
   - Impact: Agents boot into the wrong feature context.
   - Recommendation: Point SPECKIT at `specs/066-offline-banner-debounce/spec.md` until `plan.md` exists.

9. **[Standards]** User Story 2 cites the wrong i18n key for Shopping Share Sheet

   - Recommendation: Fix US2 copy to match the scope table.

### Low
