# Code Review: master (whole codebase)

## Summary

Full-codebase review by four parallel subagents: Security, Business Logic, Architecture+Standards, Performance. Overall the codebase is solid: Keychain usage, entitlements, WebView isolation, CRDT merge semantics and several hot paths (debounced sync, equatable rows, downsampled decodes) check out clean. The material risks cluster around three themes: real credentials in source, timer-sync/action queues that lose events under concurrency, and main-thread work in Discover/search hot paths.

Skipped areas: none — but dependency direction (extensions), i18n keys, and Y.Doc merge semantics were checked and returned no findings.

## Findings (sorted by priority)

### Critical

1. **[performance]** Discover recipe grids render eagerly and retain every decoded image.
   - `DiscoverRecipeCardGrid` uses a plain `VStack`/`ForEach` ([DiscoverRecipeCard.swift](RecipeScalerNative/Views/Discover/DiscoverRecipeCard.swift:105)); each card keeps its decoded `UIImage` in `@State loadedImage` ([DiscoverRecipePreviewImage.swift](RecipeScalerNative/Views/Discover/DiscoverRecipePreviewImage.swift:69)), bypassing NSCache eviction.
   - Impact: 60+ public recipes ≈ 80–100+ MB retained; launch/scroll jank, jetsam risk on older devices.
   - Recommendation: switch to `LazyVGrid`; read images only through `DiscoverImageMemoryCache` instead of `@State`.

### High

1. **[security]** Real production bearer token, user ID and recovery seed phrase are hardcoded in [DebugSimulatorAutoLogin.swift](RecipeScalerNative/App/DebugSimulatorAutoLogin.swift:21).
   - Runtime gating (`#if DEBUG` + simulator) is correct, but the values sit in the repo and git history forever.
   - Recommendation: inject via gitignored xcconfig/launch env with placeholder fallback; rotate token and seed now.

2. **[business-logic]** Single-slot Live Activity action queue drops cross-timer actions ([TimerLiveActivityActionQueue.swift](RecipeScalerNative/LiveActivity/TimerLiveActivityActionQueue.swift:46)).
   - Second enqueue overwrites the first: with two timers, Pause A then Pause B loses A's action while A's UI shows paused.
   - Recommendation: store an array of pending actions (append + drain-all) or key by timer id.

3. **[business-logic]** Outbound timer-sync removal matches by `timerId`, deleting newer events enqueued mid-round-trip ([TimerSyncService.swift](RecipeScalerNative/Services/TimerSyncService.swift:273)).
   - Rapid create→pause / resume→extend sequences silently lose events on other devices.
   - Recommendation: match on unique event `id`; remove only the exact events sent. Related medium finding below: verify whether `syncedEvents` returns event IDs vs timer IDs.

4. **[business-logic]** Unclamped scale factor can trap `Int(...)` and create a persisted crash loop ([YDocRecipeDetailView.swift](RecipeScalerNative/Views/YDocRecipeDetailView.swift:971)).
   - A long-digit quantity edit yields a finite-but-huge persisted factor; every subsequent open of the recipe crashes until storage is cleared.
   - Recommendation: clamp factor like the servings setter; clamp products before `Int` conversion (cf. `TimerSnapshot.clampingInt`).

5. **[architecture]** `TelegramConnectionView.swift:197` reads `AuthService.shared` directly, bypassing the composition root.
   - Untestable view; silent fallback to `AuthService.Standalone` when container is absent returns a different userId.
   - Recommendation: `@Environment(AuthService.self)` injection like sibling views.

6. **[architecture]** `YjsSyncService.swift` is 4685 lines handling socket lifecycle, CRDT orchestration, offline queue, timers, description bridge, auth handshake and UI state in one `@MainActor` class.
   - Recommendation: extract `SocketConnectionManager`, `OfflineQueueDrainer`, `TimerEventForwarder`, `DescriptionSyncBridge`; keep a thin façade.

7. **[standards]** `FeatureAdoptionDetailView.swift:162` renders user-facing text in system SF font, violating the Martian typeface rule.
   - Recommendation: use `AppTypography.bodySemibold` / `.body`.

8. **[performance]** Every keystroke in recipe-list search re-sorts the whole collection on main with regex-based comparisons ([RecipeListView.swift](RecipeScalerNative/Views/RecipeListView.swift:189)) although `collectionIndex.live` is already pre-sorted.
   - Recommendation: reuse `collectionIndex.live` (as `CollectionFolderView` does) or cache display names per entry.

9. **[performance]** Search builds a highlighted `AttributedString` for every matched row on main per keystroke ([RecipeListSearchStore.swift](RecipeScalerNative/ViewModels/RecipeListSearchStore.swift:147)).
   - Recommendation: compute highlights lazily per visible row keyed on `(id, tokens)`.

### Medium

**Security**
1. Seed phrase stored via KeychainAccess without `.accessibility(.afterFirstUnlockThisDeviceOnly)` ([AuthService.swift:254](RecipeScalerNative/Services/AuthService.swift:254)) — inconsistent with hardened `SharedAuthStore`.
2. URL builders interpolate IDs/usernames without percent-encoding (DiscoverAPI, AssistantAPI, RecipeLLMParseAPI, RecipeImageUploadAPI) — standardize on `URLComponents` or a shared `encodePathSegment`.

**Business logic**
3. Shopping intent drainer clears the queue before executing and swallows failures with `try?` ([ShoppingIntentActionQueue.swift](RecipeScalerNative/AppIntents/ShoppingIntentActionQueue.swift:48)) — offline cold start permanently loses enqueued items.
4. `TimerManager.addTime` ignores `isPaused`: extending a paused timer discards the paused interval ([TimerManager.swift:276](RecipeScalerNative/Services/TimerManager.swift:276)).
5. `processedEventKeys` wipe (>200 entries) can replay stale remote timer events ([TimerSyncService.swift:115](RecipeScalerNative/Services/TimerSyncService.swift:115)) — evict oldest instead of `removeAll()`.
6. `syncedEvents` response consumed as timer IDs though naming suggests event IDs — cross-check web/server contract and pin with a test.
7. Remote-event ordering trusts wall-clock comparisons across devices (`applyRemoteEvent`, `replaceTimersFromServer`) — clock skew silently drops legitimate pause/resume.
8. Dead intent files reference non-existent `ShoppingIntentAction` cases and aren't in the Xcode target (`AddRecipeIngredientsToShoppingListIntent`, `CheckOffShoppingItemIntent`) — implement or delete.

**Architecture / Standards**
9. `PublicCachedImageView`/`RecipeCachedImageView`/`RecipeDetailImageSection` call service `.shared` directly instead of environment-injected instances owned by AppContainer.
10. Three files construct private `Logger` instances bypassing `AppLog` NDJSON journal (`YjsSyncService`, `DocumentManager`, `TimerLiveActivityIntentPerformer`) — half of the sync debug trail missing from `pull-app-logs.sh`.
11. `LLMParseError.server(message:)` surfaces raw server strings to users, bypassing the `ServerErrorCode` localization contract.
12. `DocumentManager.swift` (1638 lines) mixes CRUD, SQLite persistence, parsing and queue application — extract parser + store protocol.

**Performance**
13. Public-image cache issues a conditional GET on every cell appearance even on fresh disk hits ([PublicImageCacheService.swift](RecipeScalerNative/Services/PublicImageCacheService.swift:40)) — add freshness TTL; move `fileExists` off-main.
14. `TimerSyncService.saveState` JSON-encodes the entire unbounded pending queue into UserDefaults on main per event; sync re-parses each payload it serialized itself ([TimerSyncService.swift](RecipeScalerNative/Services/TimerSyncService.swift:459)) — cap/coalesce queue, store raw bodies.
15. Yjs hot path persists the full document snapshot after each flush and re-merges bootstrap + entire queued increments every 400 ms during offline typing ([YjsSyncService.swift](RecipeScalerNative/Services/YjsSync/YjsSyncService.swift:2714)) — throttle persistence, incremental rebuild.
16. `AvatarImageService` decodes on main actor with an unbounded NSCache — decode off-main, set count/cost limits.
17. Cache-size enforcement scans and stats every cached file after every download; orphaned etag metadata accumulates in UserDefaults ([PublicImageCacheService.swift:179](RecipeScalerNative/Services/PublicImageCacheService.swift:179)).

### Low

**Security**: absolute server-supplied image URLs accepted without host allowlist; unredacted userId in WatchCredentialsBridge logs; APNs push token in plain UserDefaults + logged prefix; client relays arbitrary import URLs (server-side SSRF surface — verify backend validation).

**Business logic**: StartTimerIntent labels combined h+m timers as `.seconds`; empty unit defaults to grams for unitless quantities ([IngredientData.swift:184](RecipeScalerNative/Models/YDoc/IngredientData.swift:184)); server timer type hardcodes `.minutes` and nutrition patch wipes local `extra` fields; Discover root/recipe models lack the generation-counter stale-response protection their siblings have.

**Architecture / Standards**: `AccountView.init` reaches into `AppContainer.shared` for logout teardown; `TimerExampleView` demo compiled into production target; ~20 SF Symbol `.font(.system(size:))` sites (cosmetic only); manual `buildRequest`+`data(for:)` in DiscoverAPI/RecipeLLMParseAPI instead of `requestJSON`.

**Performance**: formatter churn (ISO8601/Date/NumberFormatter constructed per call/per render across TimerSyncService, YjsSyncService, AssistantMessageFooter, RecipeStepsSection); `replaceTimersFromServer` delete-all-and-reinsert on every server pull even without changes.

## Recommendation

**Changes Requested.** The critical Discover memory issue and the three high business-logic findings (Live Activity queue, timer-sync event loss, scale-factor crash loop) are user-visible correctness/memory bugs worth fixing before the next release. The hardcoded production credentials should be rotated and removed from source immediately regardless of release timing. Architecture decomposition (YjsSyncService) is important but can be scheduled as refactoring work.
