## Findings (sorted by priority)

### Medium

1. **[Standards]** Stale doc-comment in `OfflineBannerGate.swift:8`
   - The class-level comment said the gate updates from `AppShellView.onChange(of: connectionState)`, but iteration 2 switched the subscription to `networkReachable`. This contradicted the file's central design decision and FR-007 of the spec.
   - Impact: future maintainer could revert to `connectionState` and reintroduce the airplane-mode bug.
   - Recommendation: **FIXED** — comment updated to `onChange(of: networkReachable)` with the monotonicity rationale preserved.

2. **[Architecture]** `AccountView.#Preview` does not inject `OfflineBannerGate`
   - `AccountView` reads `@Environment(OfflineBannerGate.self)` (new line 22). The `#Preview` at `AccountView.swift:951-959` only injects `coordinator`, so opening the preview will trap on first render of `accountSection`.
   - Mitigating context: the preview was **already broken before this PR** — it also fails to inject `YjsSyncService`, `RemindersSyncService`, `FeatureAdoptionStore` (all `@Environment(Type.self)` reads). This PR adds one more missing injection but does not newly introduce the pattern.
   - Impact: Xcode canvas crashes for `AccountView`; production paths are unaffected (all route through `ContentView.appEnvironment(container)`).
   - Recommendation: **DEFERRED** — out of scope for this PR (pre-existing preview hygiene debt across 4+ services). A separate cleanup that routes the preview through `.appEnvironment(container)` would fix the whole class of bugs at once.

### Low

3. **[Architecture]** `networkReachable` violates Swift Bool naming convention
   - Swift API guidelines and the project convention dictate Bool properties use `is*` prefix (`isConnected`, `isEmpty`). The private backing var is already `isNetworkReachable`.
   - Impact: cosmetic / API ergonomics. Public property, so rename gets harder over time.
   - Recommendation: **DECLINED with documented rationale** — renaming the public computed to `isNetworkReachable` would require renaming the private backing var in 8 internal call sites, expanding the diff purely for aesthetics. Instead, kept the public name `networkReachable` and added a doc comment explaining the coexistence with the private `isNetworkReachable`. This is a deliberate trade-off, not an oversight.

### Verified clean (no findings)

- **Business logic**: `OfflineBannerGate` state machine is correct under `@MainActor` serialization. `armTask?.cancel()` + `Task.isCancelled` guard closes the stale-completion window. Single-flight invariant holds across `update(true) → update(false) → update(true)` sequences. No retain cycle (`[weak self]`). Cold-start race covered by `.onAppear` arm + `onChange` firing after NWPathMonitor's first callback. Background/foreground interaction matches spec (no flash on unlock, gate not stale on return). Test coverage satisfies FR-011 and all spec positive invariants.
- **Composition root**: `OfflineBannerGate` constructed in `AppContainer.init` (peer of `SystemBannerStore`), injected via `.appEnvironment(_:)`, no `.shared`. Coupling direction one-way (views → read sync service). Single subscription site in `AppShellView` (verified by grep — `offlineGate.update(` appears in exactly 2 places: `onChange` writer + `onAppear` initial-state drain, matching spec FR-007). `clearForLogout()` absence is intentional and documented.
- **Dead code**: `ConnectionState.isHardOffline` extension fully removed; no references remain.
- **Xcode project registration**: both new files (`OfflineBannerGate.swift`, `OfflineBannerGateTests.swift`) registered correctly in `project.pbxproj` (PBXBuildFile, PBXFileReference, group, Sources phase).

## Recommendation

**Approved** with the medium stale-comment fix applied. The deferred preview issue is pre-existing debt; the declined rename is a documented trade-off.
