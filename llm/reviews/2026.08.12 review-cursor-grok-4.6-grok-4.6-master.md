# Code Review: master (uncommitted)

## Summary

Незакоммиченный pinch-to-zoom hero-фото (spec 064): новый `HeroPhotoPinchZoom.swift`, wiring в `AppShellView`, `RecipeCachedImageView` / `PublicCachedImageView` (`heroImageBody` only), `RecipeDetailImageSection` (`pinchZoomEnabled: !isEditing`).

Направление верное: UIKit pinch + двухпальцевый pan (чтобы однопальцевый скролл не перехватывался `MagnifyGesture`), зум рисуется корневым overlay поверх tab/nav bar, edit-mode выключен по FR-012, thumbnail’ы в списках не задеты.

Риск: **высокий**. Общий `HeroPhotoZoomContext` на `AppShellView` как `@StateObject` + `@Published heroFrame` на каждый scroll-tick делает корневой shell горячим путём. Плюс нет порога `minimumScaleDelta`, двухпальцевый pan всегда живой, нет owner-id у глобального слота.

**Области:** Business Logic, Architecture, Performance, Standards.  
**Пропущено:** Security — нет user input, authn/authz, секретов, запросов.

## Findings (sorted by priority)

### Critical

1. **[Performance]** `@Published heroFrame` пишется на каждый scroll layout и инвалидирует весь `AppShellView`.
   - Impact: `GeometryReader` в модификаторе пишет `ctx.heroFrame` при любом изменении global frame (`HeroPhotoPinchZoom.swift:77–82`). `heroFrame` — `@Published` без Equatable-skip. `AppShellView` держит context как `@StateObject` (`AppShellView.swift:83`, `151–155`), поэтому **весь** `body` shell (TabView, CTA, sheets, overlays) пересобирается на кадре скролла карточки рецепта, даже при `zoom == 1`. Это горячий путь главного экрана, не локальный layout.
   - Recommendation: не публиковать frame, пока зум не активен (non-published поле, копировать в published на pinch `.began`). Не наблюдать объект из `AppShellView`: владелец без подписки, `@ObservedObject` только у `HeroPhotoZoomOverlayHost`. Иначе починка «не ререндерить shell» сломает `opacity(isZooming ? 0 : 1)` в модификаторе — он читает context через `@Environment`, а не `@ObservedObject`, и сам на `@Published` не подписывается.

### High

2. **[Business Logic / Architecture]** Один глобальный слот без владельца: last-writer-wins между героями.
   - Impact: `HeroPhotoZoomContext` хранит один `currentImage` / `heroFrame` / `zoom`. Recipes и Discover в `TabView` остаются смонтированными (`AppShellView.swift:293–307`); неактивный таб часто **не** вызывает `onDisappear`, оба GeometryReader продолжают писать frame, `register` перезаписывает картинку. Pinch на видимом hero может зумить **чужой** bitmap в чужом/устаревшем фрейме. На push/pop `onDisappear` предыдущего hero может вызвать `unregister()` **после** `.task` нового — overlay остаётся с `currentImage == nil`, `heroFrame == .zero`, при этом `opacity` прячет живое фото.
   - Recommendation: ключ сессии (UUID / `ObjectIdentifier`). `unregister` и обновление frame только если `ctx.owner == self`. Либо держать жест локально и поднимать в overlay только снимок активного hero.

3. **[Business Logic]** Нет `minimumScaleDelta` 0.05 (FR-014 / US-4).
   - Impact: `publish()` сразу отдаёт `pinch.scale`; overlay/dim включаются при `zoom > 1.001` (`HeroPhotoPinchZoom.swift:30–36`, `220–226`). Случайное двухпальцевое касание на hero даёт ~1.01–1.2, вспышку затемнения и скрытие in-place фото.
   - Recommendation: игнорировать updates, пока `pinch.scale < 1.05`; после порога — текущий clamp. Тот же порог для `isZooming` / hide original.

4. **[Business Logic]** Двухпальцевый pan всегда активен на 1.0× и перехватывает скролл через hero.
   - Impact: `UIPanGestureRecognizer` с `minimumNumberOfTouches = 2` публикует offset уже на `.began`, даже без pinch (`HeroPhotoPinchZoom.swift:168–217`). Simultaneous — только с sibling pinch, не со scroll pan. Двухпальцевый скролл по фото (US-4) забирает catcher; overlay при scale 1 не показывается, карточка не едет. Однопальцевый скролл, скорее всего, жив (`cancelsTouchesInView = false`, pan требует 2 пальца).
   - Recommendation: включать pan только пока pinch в `.began`/`.changed` **и** scale прошёл delta; либо `shouldRecognizeSimultaneouslyWith` scroll pan при `zoom <= 1`.

5. **[Performance]** Каждый тик pinch — три (до шести) `@Published` записи → снова весь shell.
   - Impact: `onChanged` пишет `zoom`, `offset`, `pinchAnchor` по отдельности (`HeroPhotoPinchZoom.swift:88–92`). Pinch и pan оба зовут `publish()` на `.changed` — до шести `objectWillChange` на кадр. Вместе с п.1 pinch дёргает tab/nav/timer chrome, которому зум не нужен.
   - Recommendation: один mutating API / published `struct Snapshot` и один `objectWillChange`. После изоляции наблюдения (п.1) грязнится только overlay.

6. **[Standards / Business Logic]** Release-анимация не уважает Reduce Motion (FR-016).
   - Impact: `withAnimation(.smooth(duration: 0.20))` (`HeroPhotoPinchZoom.swift:96–100`) — фиксированные 200 ms. Явный `withAnimation` не отключается Reduce Motion. В проекте уже есть `@Environment(\.accessibilityReduceMotion)` (`AssistantComposer`). Утверждение плана, что `.smooth` «уважает Reduce Motion», неверно.
   - Recommendation: при Reduce Motion — snap без анимации (`Transaction.disablesAnimations = true`); иначе оставить 0.20s `.smooth`.

### Medium

7. **[Architecture]** Optional environment — тихий no-op вне AppShell; overlay не покрывает sheets.
   - Impact: default `nil` (`HeroPhotoPinchZoom.swift:55–57`). Без `AppShellView` жест не ставится (`ctx != nil`). `#Preview` и DEBUG studio без shell выглядят «подключёнными» и ничего не делают. Overlay висит на `tabView` **до** `.sheet` (`AppShellView.swift:151–165`) — зум под модалкой.
   - Recommendation: DEBUG assert, если `isEnabled && uiImage != nil && ctx == nil`. Overlay на той presentation, которая должна перекрыть chrome. Preview с `@StateObject` + overlay + реальным `UIImage`.

8. **[Architecture]** Cached image views завязаны на chrome AppShell.
   - Impact: комментарии в `RecipeCachedImageView` / `PublicCachedImageView` называют `AppShellView` хостом overlay. Виджет картинки больше не самодостаточен: любой новый shell/preview/sheet должен копировать пару environment + overlay. Spec/plan держали состояние в `@GestureState` на модификаторе.
   - Recommendation: UIKit+overlay оставить в этом файле; AppShell — только chrome-host. Image views не должны предполагать конкретного владельца.

9. **[Standards]** `#Preview` не упражняет фичу.
   - Impact: оба preview с `uiImage: nil` и без context (`HeroPhotoPinchZoom.swift:292–312`). Catcher не создаётся; enabled/disabled холсты одинаковые.
   - Recommendation: preview с context, overlay и stub `UIImage`; второй — `isEnabled: false` с той же картинкой.

10. **[Standards]** Комментарий `pinchZoomEnabled` противоречит дефолту.
    - Impact: «по умолчанию включён только когда `fullWidthHero`» vs `var pinchZoomEnabled: Bool = true` (`RecipeCachedImageView.swift:22–24`). Фактический гейт — модификатор только на `heroImageBody` + `uiImage != nil`. Thumbnail’ы в списках безопасны. `PublicCachedImageView` opt-out не имеет.
    - Recommendation: поправить комментарий; при необходимости тот же флаг на Public.

## Recommendation

**Changes Requested.** Фича по UX-замыслу правильная (inline zoom поверх chrome, strict return, edit-mode off, только hero), но текущая модель состояния на корневом `ObservableObject` даёт jank на скролле, гонки между вкладками/навигацией и расхождение с FR-014/FR-016. Сначала: не публиковать `heroFrame` на idle scroll, ключ владельца, порог 0.05, pan только во время активного pinch, Reduce Motion. После этого — подписка модификатора на `isZooming`, иначе hide original сломается.
