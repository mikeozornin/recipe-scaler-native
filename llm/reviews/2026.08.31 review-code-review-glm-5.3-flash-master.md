# Code Review: master (незакоммиченные изменения, spec 074)

**Дата**: 2026-08-31 · **Модель ревьюеров**: GLM-5.3-Flash · **Вердикт**: 🔴 Changes Requested

## Summary

Ревью переноса ассистента из FAB в таббар + удаления Import-таба (spec 074). Проверены 3 области параллельными субагентами: Business Logic, Architecture, Standards. Security пропущена — движок импорта не менялся, переехали только точки входа.

Общая оценка: **архитектура изменения выдержана** — фейк-таб-паттерн переиспользован корректно, слои не нарушены, i18n чистый, PI-1/PI-2 закрыты тестами. Но найден **один критичный регресс**: на iOS 26.0–26.1 полностью пропадает панель таймеров. Плюс две high: потеря payload при гонке внешний запрос/тап и системный шрифт табов на iOS 26.

## Findings

### Critical

1. **[business-logic] На iOS 26.0–26.1 полностью пропадает панель мобильных таймеров** — подтверждено по коду
   - `AppShellView.swift:405` — гейт разделения путей `#available(iOS 26.0)` → `modernTabView`; но оба механизма таймер-панели внутри modern-пути защёлкнуты на **26.2**: `MobileTimerAccessoryModifier` (`:596`) и `ModernTabBottomBarModifier` (`:636`) ниже 26.2 возвращают `content` без изменений. Fallback `safeAreaInset(.bottom)` + `mobileTimerPanel` есть только в legacy `tabRoot`.
   - **Impact**: на iOS 26.0/26.1 активные таймеры невидимы в любом виде — молчаливая функциональная регрессия против прежнего поведения, где эти версии шли через legacy-путь. Дополнительно `ModernTabBottomBarModifier` не учитывает `suppressPanelSafeAreaInset`.
   - **Recommendation**: поднять гейт modern-пути до 26.2 (26.0/26.1 остаются в проверенном legacy-пути) — минимальный фикс; либо добавить в `modernTabRoot` fallback-ветку `< 26.2`. Верифицировать на симуляторах 26.0/26.1 — спека тестирует только iOS 18 и «iOS 26» (26.2+), разрыв покрытием не ловится.

### High

2. **[business-logic] Гонка: внешний open-запрос + тап по ассистенту в одном кадре → payload теряется (PI-5)**
   - `AppShellView.swift:158–175, 297–302`: если `pendingAssistantOpenRequest` и `pendingAssistantTabOpen` меняются до одного обновления SwiftUI, `routePendingAssistantOpenRequest` кладёт payload в `assistantOpenRequest`, затем обработчик таба вызывает `openAssistantManually()`, который безусловно делает `assistantOpenRequest = nil`. `AssistantSheet.onChange(of: openRequest)` видит только nil — внешнее сообщение (autosend) молча теряется, пользователь получает пустой чат.
   - **Impact**: единичный запрос ассистента теряется; окно — один кадр, но прямое нарушение PI-5.
   - **Recommendation**: в `onChange(of: pendingAssistantTabOpen)` проверять приоритет внешнего запроса (`guard coordinator.pendingAssistantOpenRequest == nil else { … }`) или не сбрасывать `assistantOpenRequest`, если запрос зароучен в этом же обновлении.

3. **[standards] На iOS 26 подписи трёх табов (recipes/shopping/profile) рендерятся системным шрифтом вместо Martian**
   - `AppTabBarLabel` с `AppTypography.tabBar` реально используется только у таба-ассистента (`AppShellView.swift:455–458`); остальные заданы через `Tab(title:systemImage:value:)` (`:431+`), где шрифт применить негде, а кастомный `label:` при `role: .search` игнорируется платформой.
   - **Impact**: нарушение правила «весь текст — Martian» на всех iOS 26+. Похоже на платформенное ограничение нового Tab API, но как осознанный трейд-офф в спеке не зафиксировано.
   - **Recommendation**: зафиксировать в `specs/074-assistant-tab-entry/spec.md` как платформенное ограничение iOS 26, либо (если неприемлемо) оставить единый legacy-рендер табов.

### Medium

4. **[standards] Дублирование `openAssistantManually()` в adoption-CTA — незавершённый рефакторинг**
   - `AppShellView.swift:186–196`: `openAssistant` повторяет 4 строки хелпера `openAssistantManually()` (`:169–175`) вместе с комментарием про stale payload. Риск расхождения manual-open путей (тот же класс багов, который этот код чинит).
   - **Recommendation**: в `openAssistant` вызывать `openAssistantManually()`.

5. **[architecture/business-logic] Композер: поле больше не дизейблится во время транскрибации голоса**
   - `AssistantComposer.swift:463`: после сплита на `AssistantComposerChrome` (владеет `voiceRecorder`) и wrapper (владеет `TextField`) условие дизейба сократилось до `.disabled(isSending)` — прежнее `|| voiceRecorder.state == .transcribing` потеряно.
   - **Impact**: во время транскрипции поле редактируемо; возможна отправка частичной транскрипции и конфликт с `appendTranscription`.
   - **Recommendation**: прокинуть состояние транскрипции в wrapper (`isInputLocked`) или вернуть условие на уровне Chrome; зафиксировать в спеке, если упрощение сознательное.

6. **[business-logic] Новый продовый вход импорта «+» → «Импортировать рецепт» не покрыт тестами; PI-3 без E2E**
   - `RecipeListPage.tapImportRecipe()` (`RecipeListPage.swift:111`) добавлен, но ни один спек его не вызывает — import-спеки проверяют debug-путь `-OpenTab=import`. PI-3 (повторный тап после dismiss) покрыт только на уровне машины состояний.
   - **Recommendation**: E2E: `tapImportRecipe()` → `importSheet`; спек ассистента: открыть → dismiss → повторный тап → sheet.

7. **[standards] Мёртвые `tabImport`-идентификаторы в обоих реестрах**
   - `AccessibilityIdentifiers.swift:21` и `Selectors.swift:23`: `tab_import` остался, хотя таб удалён из обеих панелей (живой только debug-путь `-OpenTab=import`, который идентификатор на экран не вешает).
   - **Recommendation**: удалить или пометить как debug-only контракт.

8. **[standards] Новые a11y-идентификаторы в snake_case вместо kebab-case**
   - `tab_assistant`, `recipe_list_add_new`, `recipe_list_import` — по правилу E2E должно быть kebab-case; в проекте уже есть kebab-case-блок (072), т.е. конвенция двойная.
   - **Recommendation**: мигрировать новые на kebab-case (вместе с `UIA`) либо зафиксировать допустимость legacy snake_case в доке реестра.

### Low

9. **[architecture] `AppTab.importTab` остался с полным набором UI-метаданных и живой веткой в `handleTabSelection`** — нужен комментарий-контракт («debug-only entry, вне таббара со спеки 074») или отдельный тип для `-OpenTab`-парсинга.
10. **[business-logic/architecture] Хвосты рефакторинга AssistantComposer**: `@Environment(AssistantRecipeContext.self)` в `AssistantSheet` не читается; `effectiveContextRecipeId` в Chrome, похоже, мёртвый (`_ =`-подписка без использования); doc-комментарий «Shared… Used inside legacy modal» описывает структуру неверно; `AssistantComposerChrome.topContent: () -> AnyView` — лишнее стирание типа (сделать generic `TopContent: View` по образцу соседних модификаторов).
11. **[standards] Возможные мёртвые члены AppShellView после переноса геометрии**: проверить `mobileTimerPanelChevronNamespace`; удалить задвоенный комментарий «Spec 040» (`:179–180`).
12. **[business-logic] `docs/UI.md:85` всё ещё описывает Assistant FAB** со ссылкой на удалённый `AssistantFabStyle.swift` — обновить на таб-энтри.

## Проверено — чисто

- **PI-1/PI-2**: `selectedTab` никогда не становится `.assistant` (проверены все присваивания); logout чистит флаг — юнит-тест покрывает.
- **Импорт-точки сохранены**: Recipes «+», CollectionFolder «+», adoption CTA, debug `-OpenTab=import`, silent deep-link импорт; двойной презентации нет (единственный `.sheet(item:)`).
- **Composition root**: новых `.shared` нет; `RecipesAddToolbarMenu` переиспользуется обоими экранами, коллбеки инжектятся.
- **Coordinator layering**: координатор хранит только флаг, презентацию делает view через `onChange` — слои не протекают.
- **PI-6**: `.searchable`/`tabViewSearchActivation` не прикреплены; `role: .search` — только placement.
- **i18n**: хардкода нет, все новые ключи существуют в `Localizable.xcstrings`, fallback-паттернов нет.
- **Удаление FAB/TabBarDiscovery**: висячих ссылок нет, pbxproj консистентен, тесты удалены вместе с кодом, оставшиеся проверки не ослаблены.
- **PI-7**: sparkles покрыт автоматически через `AppTab.allCases` в UIKit-тесте символов.

## Recommendation

**Changes Requested.** До коммита обязателен фикс находки 1 (регресс таймер-панели на iOS 26.0–26.1) — это блокер релиза. Находки 2–3 желательно решить в этом же изменении (гонка PI-5 и решение по типографике табов зафиксировать явно). Остальное можно добить отдельным cleanup-проходом.
