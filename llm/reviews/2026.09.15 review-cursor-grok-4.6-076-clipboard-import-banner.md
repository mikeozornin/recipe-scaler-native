# Code Review: 076-clipboard-import-banner

## Summary

Фича 076 (баннер импорта URL из буфера) в целом совпадает со спекой: store в composition root, чтение `.string`/`.urls` только по тапу Import, свои Copy через `AppPasteboard`, i18n и a11y на месте.

Ревью: **Security**, **Business Logic**, **Architecture**, **Standards**.  
**Performance** пропущен: нет запросов/циклов по данным, только `detectPatterns`/`hasURLs` на foreground.

Стандарты: замечаний нет. Есть несколько **high** по async lifecycle, consume и inbound-гейту.

Субагенты: [Security](b5dc71b6-7cff-43a8-b1ff-0f7c6107da94), [Logic](9c40b19e-fc47-4556-9e7a-9ebecbefaf43), [Architecture](84f1a054-1163-4f56-8a42-064f4818c2de), [Standards](6c808191-2276-4e78-be48-47202e8e65b5).

## Findings (sorted by priority)

### High

1. **[Security / Architecture]** `presentClipboardImport` / `seedTextForImport` не перепроверяют сессию после `await`.
   - Impact: `Task` читает буфер и может открыть sheet с auto-submit уже после logout / смены аккаунта (`AppShellCoordinator` живёт на контейнере).
   - Recommendation: Захватить `evaluateGeneration` (и userId) до `plainText()`; после await — no-op при смене generation/сессии. Перед `presentImport` проверить `isAuthenticated`. Отменять Task из `clearForLogout`.

2. **[Business Logic]** Любой успешный `ImportRecipeSheet` вызывает `markConsumed()`.
   - Impact: Photo/file/ручной текст тоже помечают текущий `changeCount` буфера consumed. Баннер для этой ссылки больше не появится в процессе, хотя импортировали не её. После открытия sheet evaluate обнуляет `visibleChangeCount`, поэтому consume падает на `pasteboard.changeCount`.
   - Recommendation: `markConsumed` только для clipboard-seeded presentation (`seedText` / флаг), не на каждый `onImport`.

3. **[Architecture]** `AppPasteboard.onOwnWrite` — process-wide callback с сильным захватом store, без teardown.
   - Impact: Store удерживается до конца процесса; при новом `AppContainer` колбэк перезаписывается, не снимается; возможен вызов `@MainActor` с неisolated setter. Это не `.shared`, но тот же класс скрытой проводки, что composition root старается убрать.
   - Recommendation: `[weak clipboardImport]`, hop на MainActor, `onOwnWrite = nil` в logout/invalidation.

4. **[Security / Business Logic]** Гейт pending Share/deep-link смотрит live UserDefaults уже после consume.
   - Impact: `evaluate` в `Task`; `onAppear` может съесть `pendingRecipeId` в том же цикле. Баннер может вылезти поверх inbound-открытия рецепта (FR-010). Обратно: после pending нет повторного evaluate — баннер может застрять hidden.
   - Recommendation: Снять snapshot pending синхронно до consume; держать inbound-in-progress до конца навигации; evaluate при изменении pending.

### Medium

5. **[Architecture]** `withClipboardImportBanner` владеет `.sheet(item: importPresentation)` для всего импорта, не только оверлея буфера.
   - Impact: Tab Import / CTA и clipboard-seed делят обёртку с clipboard-именем — легко сломать sheet, чиня баннер.
   - Recommendation: Sheet оставить на shell; wrapper — overlay, FAB lift, evaluate.

## Recommendation

**Changes Requested.** Четыре high: logout-race на Import tap, ложный consume, OS-фасад без teardown, inbound-гейт. Standards чистые. Не блокеры продукта для ручного теста, но перед merge стоит закрыть 1–4.
