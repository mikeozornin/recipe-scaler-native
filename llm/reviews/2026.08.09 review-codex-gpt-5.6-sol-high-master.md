## Summary

Changes requested. The range contains two serious socket-session isolation defects in the Yjs synchronization path. A delayed mutation or handshake response from an old connection can cross a reconnect or account switch and operate on the current account's collection document. The new state-vector handshake also removes a canonical-state recovery property and can leave a locally truncated collection looking fully synchronized.

The feature-adoption media pipeline has several integration failures: localized video variants overwrite each other, generated videos are not copied into the application bundle, the walkthrough capture records a static fallback, and normal verification permits required media to be absent.

## Findings

### Critical

1. **[Architecture / Security] Queued Yjs mutations can cross socket and account boundaries**
   - Files: `RecipeScalerNative/Services/YjsSync/YjsSyncService.swift:1324-1335, 2087-2108`
   - Description: `emitSyncUpdate` creates serialized tasks that wait behind `syncEmitTail` and may sleep for large payloads. `teardownSocket()` only clears the stored tail reference; it does not cancel existing tasks or bind them to the socket session and user that created them. When an old task resumes, it reads the service's current `socket` and can emit its captured payload through a newly authenticated connection.
   - Trigger: A queued update exists while the app reconnects, logs out, or switches accounts, and the replacement socket authenticates before the old task resumes.
   - Impact: Stale writes can be submitted after reconnect. More seriously, collection updates omit `recipeId`, so a collection update captured for account A can be applied to account B's collection document, causing cross-account data exposure or corruption.
   - Recommendation: Capture the originating socket identity, socket-session UUID, and user ID in every queued task. Revalidate all three after every suspension and immediately before emission. Cancel the complete emit chain during teardown and check cancellation before using the socket.

### High

2. **[Architecture / Security] The new sync handshake is not scoped to its originating socket session**
   - Files: `RecipeScalerNative/Services/YjsSync/YjsSyncService.swift:1758-1775, 1871-1874, 2376-2424`; `RecipeScalerNative/Services/YjsSync/SyncEventHandler.swift:58-60`
   - Description: `emitSyncStep1` awaits state-vector generation before reading the mutable current socket, without retaining the initiating session. The new shared `sync_step2` callback similarly reaches `handleSyncStep2` without the originating socket-session identity. This differs from lifecycle callbacks that reject stale clients with `isCurrentSocketSession`.
   - Trigger: A reconnect or account switch occurs while a state vector is being calculated, or an old socket dispatches a buffered `sync_step2` after a replacement session starts.
   - Impact: An old state vector can be emitted on the new account's socket, or an old account's update can be merged and persisted under the current account's collection key.
   - Recommendation: Carry the socket-session ID, expected user ID, and document key through both request and response paths. Reject the operation if any identity changed before emission or application. Prefer per-session event callbacks that are invalidated atomically during teardown.

3. **[Data Integrity] A truncated local collection can be accepted as fully synchronized**
   - File: `RecipeScalerNative/Services/YjsSync/YjsSyncService.swift:2387-2414`
   - Description: The new state-vector handshake considers a tiny no-op `sync_step2` sufficient when any non-empty local snapshot exists. A damaged snapshot with hard-deleted entries can still have a state vector that matches the server, so the server correctly sends no missing operations even though the visible collection is incomplete. The previous canonical `load_document` path could repair this state.
   - Trigger: A locally persisted collection is truncated but retains a saturated state vector, and no pending collection write triggers the server's truncation guard.
   - Impact: Recipes can remain indefinitely hidden on the device, appearing as persistent data loss.
   - Recommendation: After collection handshake, compare live entries with a persisted high-water mark or other trusted local count. If truncation is detected, delete the poisoned snapshot and invoke the existing server-recovery path using an empty state vector before permitting collection writes.

4. **[Integration] Video installation overwrites locale/theme variants and does not bundle the result**
   - Files: `scripts/install-feature-adoption-media.sh:9-12, 41, 52-75`; `RecipeScalerNative/Utils/GuideAssetResolver.swift:46-57`; `RecipeScalerNative.xcodeproj/project.pbxproj`
   - Description: Every locale/appearance directory produces the same MP4 basename, but installation recursively copies all files into one flat directory. Later copies overwrite earlier variants. The resolver expects names such as `<base>_ru_dark.mp4`. In addition, the generated `Resources/GuideVideos` directory and its MP4 files are absent from the application's Copy Bundle Resources phase.
   - Trigger: Run the documented capture/install pipeline, build the app, and open a guide with video.
   - Impact: Only an arbitrary source variant survives installation, and the built app cannot resolve even that file from `Bundle.main`; users see the developer placeholder or the wrong locale/theme.
   - Recommendation: Rename each installed video to `<base>_<locale>_<appearance>.mp4`, fail on destination collisions, add the generated video directory/files to the app target, and assert that every expected MP4 is present in the built `.app`.

5. **[Business Logic / Integration] Walkthrough capture records a static fallback scene**
   - Files: `scripts/capture-feature-adoption-media.sh:196-200`; `RecipeScalerNative/Utils/DebugLaunchOptions.swift:66-69`; `RecipeScalerNative/Views/GuideMediaStudioView.swift:80-107, 355-415`; `specs/040-feature-adoption-guides/guide-media-manifest.json:215-231`
   - Description: Capture launches `imported_recipe.walkthrough` or `connected_telegram.walkthrough` and passes the same value as `GuideMediaSequence`. No committed app code consumes `guideMediaSequence`. The scene catalog accepts these unknown IDs based on their item prefix, classifies them as `.realApp`, and falls through to the generic creation-map card.
   - Trigger: Run feature-adoption video capture for either walkthrough.
   - Impact: The advertised 12-second walkthrough is an unmoving fallback card rather than the documented import or Telegram flow.
   - Recommendation: Implement explicit timed walkthrough scenes that consume `guideMediaSequence`, or record and concatenate the manifest's defined constituent scenes. Reject unknown scene IDs instead of accepting any ID with a recognized prefix.

### Medium

6. **[SwiftUI / UX] System theme always selects light guide media**
   - File: `RecipeScalerNative/Utils/GuideAssetResolver.swift:35-53`
   - Description: Appearance selection treats only an explicit `.dark` preference as dark. The default `.system` preference therefore resolves to `light` regardless of the effective OS color scheme.
   - Trigger: Leave theme set to System, use device Dark Mode, and open a media-backed guide.
   - Impact: Light screenshots and videos appear in a dark interface and do not update when system appearance changes.
   - Recommendation: Resolve the effective SwiftUI `ColorScheme` and pass it into the asset resolver, or otherwise query the active trait environment when preference is `.system`.

7. **[Tests / Integration] Normal verification succeeds when required guide media is absent**
   - Files: `scripts/validate-feature-adoption-media.sh:73-98`; `scripts/verify-feature-adoption-guides.sh:72-74`
   - Description: Missing expected PNGs are skipped, and videos are validated only when present. The normal verification path does not enable `REQUIRE_GUIDE_MEDIA_CAPTURE=1`.
   - Trigger: Run verification from a clean or partially populated capture directory.
   - Impact: Verification can report success while all newly referenced media is missing, allowing production guide screens to ship placeholders.
   - Recommendation: Separate contract-only validation from capture/release validation. The latter must require every manifest asset for every requested locale/appearance and verify the installed application bundle, not only temporary source files.

8. **[Standards / Integration] The completed-guide preview lacks its required environment service**
   - File: `RecipeScalerNative/Views/FeatureAdoptionGuideView.swift:170-173`
   - Description: The “Done + CTA” preview no longer creates and injects `FeatureAdoptionStore`, while `FeatureAdoptionGuideView` still declares a non-optional `@Environment(FeatureAdoptionStore.self)`.
   - Trigger: Open this preview in Xcode.
   - Impact: The preview fails at runtime, removing the intended visual check for the completed CTA state.
   - Recommendation: Restore a configured `FeatureAdoptionStore`, inject it into the preview, and seed the relevant completed report value.
