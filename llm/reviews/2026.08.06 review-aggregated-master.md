#### C-1. [Security] Залитые seed phrases для 3 аккаунтов в публичном репо

- **Files**: `store/fixtures/users.yaml` (commit `e1a95cd`)
- **Description**: В коммите `e1a95cd` в репозиторий (public!) залит файл `store/fixtures/users.yaml` с тремя 12-словными mnemonic seed phrases в plaintext:
  ```yaml
  seedPhrase: "cool fork duty quick fork praise cook unfold holiday vanish pride mean"
  seedPhrase: "fun elegant copy employ mechanic trigger imitate mixture trend grid unfold health"
  seedPhrase: "want elbow air educate buzz artefact impulse illness surface history work announce"
  ```
  Каждый сопровождается фиксированными `userId`, `deviceId`, `username`. Заголовок файла буквально гласит `seedPhrase is given to App Review`.
- **Impact**: Любой в интернете может вызвать `POST /api/auth/login-with-seed` (через `scripts/store_users.py login ru|en|app-store-review`) и захватить любой из трёх аккаунтов. Два аккаунта — screenshot-аккаунты с курируемой библиотекой для App Store маркетинга; **`app-store-review`** аккаунт — тот, что использует Apple во время ревью. Атакующий может:
  - Удалить/испортить рецепты, подменить изображения на NSFW → Apple видит испорченные данные
  - Заблокировать Apple, переключив device token
  - Seed phrases — высоко-энтропийный recovery-примитив, ротация только через замену аккаунта
  - Seed для публичных профилей `mikeozornin-ru-scr` / `mikeozornin-en-scr` тоже утёк → вандализм public collections
- **Recommendation**:
  1. **Немедленная ротация**: `scripts/store_users.py provision --force` для всех трёх аккаунтов, чтобы утёкшие seeds больше ничего не открывали.
  2. **Strip из истории**: `git filter-repo --path store/fixtures/users.yaml --invert-paths` + force-push (GitHub хранит plaintext навсегда даже после удаления). Координировать со всеми, кто уже сделал pull.
  3. Перенести файл из репо: env var, gitignored-файл, или CI secret. В Python-скрипте уже есть `E2E_API_BASE` overrides — аналогичный паттерн для credentials.
  4. Добавить `store/fixtures/users.yaml` в `.gitignore` (сейчас не игнорируется — только `store/screenshots/iphone-6.9/**/*.png`).
  5. `pre-commit` hook, который реджектит `seedPhrase:` вне allow-list.

### High

#### H-1. [Business Logic] `dismiss()` failure оставляет баннер скрытым на всю сессию — расходится с комментарием и `applyFetchedBanner` guard

- **Files**: `RecipeScalerNative/Services/SystemBannerStore.swift:66-97`
- **Description**: Класс-док говорит *"после `dismiss()` очищает in-memory баннер, следующий `refresh()` вернёт `nil`, потому что сервер записал dismissal"*. На практике **единственный** call site для `refresh()` — `AppContainer.bootstrap`, который запускается **один раз за сессию**. Нет `scenePhase` / `onAppear` / polling.
- **Impact**: Если dismiss POST фейлится, `dismissedBannerIds.insert(bannerId)` и `activeBanner = nil` прячут баннер в памяти, но сервер не имеет записи о dismissal. Расхождение с комментарием *"the next cold start will re-fetch, and (if the POST truly failed) the banner will re-appear"* — в этой сессии баннер не вернётся. Cross-device расхождение: iPhone со сломанным dismiss не покажет баннер снова, но парный Watch / iPad покажет при следующем bootstrap.
- **Recommendation**:
  - **Вариант A**: персистировать `dismissedBannerIds` (или один optimistically-dismissed id) в `UserDefaults` — cross-session consistency даже при фейле POST и убийстве приложения.
  - **Вариант B** (идиоматичнее для fire-and-forget): ретрай POST на следующем `scenePhase = .background` / app will-terminate. Минимум — уточнить комментарий про "this session" vs "across sessions on other devices".
  - Добавить тест `dismiss()` failure → cold start.

#### H-2. [Architecture] App Group IPC-ключ задублирован как raw string literal через модульные границы

- **Files**: `RecipeScalerNative/Routing/DeepLinkRouter.swift:60-62` (reader), `ShareExtensionUI/ShareView.swift:189-191` (writer)
- **Description**: Контракт pending-recipe-id: reader использует типизированную константу, writer (Share extension, другой модуль) вынужден повторить literal, потому что константа в `DeepLinkRouter` (app target) — невидима для Share target.
  ```swift
  // RecipeScalerNative/Routing/DeepLinkRouter.swift
  static let pendingRecipeIdKey = "routing.pendingRecipeId"
  // ShareExtensionUI/ShareView.swift
  AppGroup.userDefaults?.set(id, forKey: "routing.pendingRecipeId")
  ```
- **Impact**: Cross-process contract drift, который `AppGroup` enum и был создан предотвращать (его docstring буквально так и говорит). Будущий rename в `DeepLinkRouter` молча сломает Share → host cold-start navigation. Сейчас ключ — трёхсторонний контракт (Share пишет App Group, legacy Action пишет `UserDefaults.standard`, host читает оба), ни один не enforced компилятором.
- **Recommendation**: Промотировать ключ в cross-module facade:
  ```swift
  // RecipeScalerCore/AppGroup.swift
  public extension AppGroup {
      static let pendingRecipeIdKey = "routing.pendingRecipeId"
  }
  ```
  Оба места (`ShareView.openRecipeInHostApp()` и `DeepLinkRouter.pendingRecipeIdKey`) ссылаются на один символ. Обновить docstring у `AppGroup.id`.

#### H-3. [Architecture] Production-only mutation API `replaceShoppingItems` отгружается в Release, но вызывается только из `#if DEBUG` screenshot-seed

- **Files**: `RecipeScalerNative/Services/YjsSync/DocumentManager+ShoppingList.swift:122-141`, `RecipeScalerNative/Services/YjsSync/YjsSyncService.swift:988-991`
- **Description**: Метод wholesale-replace пользовательского shopping list (clear + insert new array) добавлен в два production-типа без `#if DEBUG` gate, но единственный call site — `DebugLaunchOptions.applyScreenshotShoppingSeedIfNeeded`, который под `#if DEBUG`. Поверхностная mutation Yjs-массива по индексу, в обход обычного CRDT-aware shopping mutation path.
- **Impact**:
  - **API surface bloat**: destructive "nuke and replace" теперь навсегда в public `YjsSyncService` API, хотя ни один production flow не использует. Будущие разработчики могут подумать, что это реальная фича.
  - **Sync layering**: обходит normal CRDT-aware mutation path, который используют `addWholeRecipeToShoppingList` / `toggleShoppingItem`. Если sync layer добавит per-item metadata / server reconciliation / undo tracking для shopping, этот метод их обойдёт.
  - **Risk surface**: любой будущий код (AppIntent, shortcut, share extension), который найдёт этот метод, может wipe'нуть список пользователя без guard.
- **Recommendation** (по предпочтению):
  1. Унести весь метод (и `DocumentManager` counterpart) под `#if DEBUG`. Doc comment "store screenshot seed" подтверждает отсутствие production-цели.
  2. Если оставлять в production — переименовать в `replaceAllShoppingItemsForScreenshotSeed` с doc warning, что он bypass'ит mutation tracking.
  3. Если это реально general-purpose primitive — отдельный spec с CRDT/reconciliation implications.

#### H-4. [Security] `NSSelectorFromString("sharedApplication")` + `perform(_:)` на `UIApplication` из Share/Action extension — риск App Store rejection

- **Files**: `ShareExtensionUI/ExtensionHostURLOpener.swift:54-62` (commit `42c5c47`)
- **Description**: Когда responder-chain walk фейлится, код падает на runtime:
  ```swift
  let sel = NSSelectorFromString("sharedApplication")
  if let appType = NSClassFromString("UIApplication") as? NSObject.Type,
     appType.responds(to: sel),
     let unmanaged = appType.perform(sel),
     let application = unmanaged.takeUnretainedValue() as? UIApplication { ... }
  ```
  `UIApplication.shared` явно unlinked из app extensions. App Review static-analyze appex binaries на selectors вроде `sharedApplication` и `openURL` против private symbol tables.
- **Impact**: Высокая вероятность binary-rejection на App Review. Defeats entire purpose of screenshot pipeline. Responder-chain branch (`candidate as? UIApplication`) безопасен, но runtime fallback переходит черту.
- **Recommendation**: Удалить `NSClassFromString` / `perform(sel)` runtime branch полностью. Полагаться на:
  1. `NSExtensionContext.open` (Today widgets, some Share hosts)
  2. Responder-chain walk
  3. App Group `routing.pendingRecipeId` IPC channel (уже реализован в коммите)

  Запись в App Group в `ShareView.swift:190` уже гарантирует, что recipe id переживёт cold start, если `open` фейлится. Runtime `sharedApplication` вызов избыточен, когда есть backup. Если оставлять fallback — валидировать против текущих App Review precedents перед submission.

#### M-1. [Business Logic] Timer notification categories / body не пере-локализуются при смене языка в runtime

- **Files**: `RecipeScalerNative/Services/TimerManager.swift:572-597, 633`
- **Description**: `464e25a` правильно переключил `registerNotificationCategories` и `content.body` с `String(localized:)` на `Bundle.currentLocalizedString(...)`. Но `registerNotificationCategories()` вызывается только из `init`. Нет observer'а `UserDefaults.didChangeNotification` в `TimerManager`. После смены языка mid-session уже зарегистрированные `UNNotificationCategory` action titles ("+1 min", "+5 min", "Delete") продолжают рендериться на языке, который был активен при конструировании `TimerManager`. Для pending `UNNotificationRequest` `content.body` заморожен на момент schedule.
- **Impact**: Юзер на русском, с запущенным таймером, переключает на английский → notification и action buttons приходят на русском, пока остальной UI на английском. Mixed-language push copy — ровно та регрессия, которую фиксит коммит.
- **Recommendation**: Re-регистрировать `UNNotificationCategory` при смене live language bundle override. Hook: `UserDefaults.didChangeNotification` observer (или expose `registerNotificationCategories()` и вызвать из `ContentView` рядом с `appLanguage = newLanguage`).

#### M-2. [Business Logic] `mapHTTPFailure` больше не проверяет `json.success` — `success: false` с пустым `error` теперь silently становится `httpError`

- **Files**: `RecipeScalerCore/Networking/APIClient+Requests.swift:117-135`
- **Description**: Старый `parseAPIFailureBody` имел `!json.success && !error.isEmpty`. Новый `parseAPIFailureMessage` проверяет только `let error = json.error, !error.isEmpty` — больше не требует `success == false`. Если сервер вернёт `{success: true, error: "..."}` на non-2xx (контракт-нарушение, но не enforced) → новый путь произведёт typed `serverError` / phrase-mapped `upstreamMessage`.
- **Impact**: Server может вернуть `success: true` + spurious error string на 503 maintenance → `ImportErrorLocalizer` surface'ит unrelated internal error text.
- **Recommendation**: Восстановить `success == false` guard внутри `parseAPIFailureMessage` для parity с предыдущим поведением. 1-line revert, сохраняет documented server contract.

#### M-3. [Business Logic] `HTTP 404:` маппится в `import.error-static` — семантически сомнительно

- **Files**: `RecipeScalerCore/Import/ImportErrorLocalizer.swift:78-80`
- **Description**: `"Could not extract content with any static method"` → `import.error-static` — это конкретный server-side failure (скраперы нашли страницу, но не смогли распарсить). Mapping `"HTTP 404:"` на тот же key конflate'ит два разных условия:
  - **404**: source URL не существует (dead link, typo, recipe deleted at source)
  - **error-static**: URL существует, контент есть, но парсер не справился
- **Impact**: Юзеры, импортирующие dead/typo URL, видят тот же текст, что и юзеры с валидным URL, но необычной разметкой. Support burden: сложно различить из логов после dismiss.
- **Recommendation**: Либо добавить отдельный key (`import.error-not-found`) для 404 case, либо мапить 404 на generic `import.error`. Если product реально хочет их схлопнуть — добавить code comment с intentional conflation.

#### M-4. [Business Logic] `AppContainer.bootstrap` стреляет `widgetPushRegistrar.registerCachedIfNeeded()` как unconstrained `Task` до того, как остальная часть `bootstrap` закончила setup sync/auth

- **Files**: `RecipeScalerNative/App/AppContainer.swift:415-417`
- **Description**: `Task { [widgetPushRegistrar] in await widgetPushRegistrar.registerCachedIfNeeded() }` детачится из `bootstrap(userId:)`. `stopForLogout()` может вызваться, пока registration в полёте → "register → unregister → register POST settles" → dangling token на сервере для userId, который уже вытерт.
- **Impact**: Редкий, но реальный race на cold launch с stale-session detection. Server будет иметь dangling token record. User-visible effect минорный (silent pushes no-op'ятся downstream `pendingLocal` guard'ами).
- **Recommendation**: Либо (a) сделать Task cancelable и cancel в `stopForLogout`, либо (b) capture `userId` в начале Task и re-check против `SharedAuthStore.userId` перед POST (mirror'ит паттерн `FeatureAdoptionStore.markFeatureInstalled`).

#### M-5. [Security] `routing.pendingRecipeId` App Group slot не имеет integrity check перед навигацией

- **Files**: `ShareExtensionUI/ShareView.swift:190` (writer), `RecipeScalerNative/Routing/DeepLinkRouter.swift:239-251` + `RecipeScalerNative/Routing/AppShellCoordinator.swift:99-103` (reader), commit `42c5c47`

  ```swift
          AppGroup.userDefaults?.removeObject(forKey: pendingRecipeIdKey)
          UserDefaults.standard.removeObject(forKey: pendingRecipeIdKey)
          return nil
      }
      // ... clean + return normalized
  }
  ```
