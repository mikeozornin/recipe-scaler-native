## Summary

Implementation корректная и хорошо покрыта тестами. Критичных проблем нет. AASA на prod отдаётся корректно (200, `application/json`, правильный `appID` и paths — современный формат `apps: []` + singular `appID`). Парсер строгий, не-UUID и чужой хост отбрасываются. Entitlements сохраняют `aps-environment`.

Headline проблемы (Architecture, medium):
- `universalLinkHosts` дублирует `Config.baseURL` и ломает E2E UL-тестирование с `E2E_OVERRIDE_API_BASE`
- Двойная доставка (`onOpenURL` + `NSUserActivityTypeBrowsingWeb`) безопасна **случайно**, без инварианта в коде
- Новая `.onContinueUserActivity` использует `.shared` shim, хотя `RecipeScalerNativeApp` держит реальный `container` — нарушение правила Composition Root

## Findings (sorted by priority)

### Medium

1. **[architecture]** `DeepLinkRouter.universalLinkHosts = ["recipe-scaler.ru", "www.recipe-scaler.ru"]` дублирует хост `Config.baseURL` и игнорирует оба `Config` enum-а (`RecipeScalerNative/Config.swift`, `RecipeScalerCore/Config/Config.swift`).
   - Impact:
     - Drift: при смене/добавлении домена (`Config.baseURL` правят, `universalLinkHosts` забывают) — UL-парсинг молча fail-open (ссылка остаётся в Safari), без сигнала в тестах.
     - **E2E parity hole прямо сейчас**: в DEBUG `E2E_OVERRIDE_API_BASE` редиректит REST+WS на `localhost:3001`, но UL-парсер всё равно требует хардкоженный хост → UL-флоу не покрыть E2E локально.
   - Recommendation: выводить whitelist из `Config.baseURL`:

     ```swift
     private static var acceptedHosts: Set<String> {
         guard let host = URL(string: Config.baseURL)?.host?.lowercased() else { return [] }
         return host.hasPrefix("www.") ? [host, String(host.dropFirst(4))] : [host, "www.\(host)"]
     }
     ```

     Либо, если нужна build-time иммунность к env override, оставить `static let` и явно задокументировать.

2. **[architecture]** Безопасность от двойной доставки Universal Link (через `.onOpenURL` и `.onContinueUserActivity(NSUserActivityTypeBrowsingWeb)` на части iOS/scene-конфигураций) — **случайная**: опирается на (a) `pending` очищается потребителем до второго колбэка и (b) `pending: Equatable` ⇒ `onChange` пропускает no-op. Ни один инвариант не задокументирован в роутере.
   - Impact: при любом рефакторинге `clear()` (или удалении в новом case) вторая доставка повторно стриггерит навигацию → flicker / двойной push в `discoverPath`.
   - Recommendation: сделать идемпотентность явной. Один уровень защиты в роутере:

     ```swift
     private static var lastHandledURL: URL?
     static func handle(_ url: URL) {
         guard let link = parse(url) else { return }
         if lastHandledURL == url { return }
         lastHandledURL = url
         shared.handle(link)
     }
     ```

     Либо (дешевле) — комментарий в doc-блоке + тест, проверяющий двойной вызов с одним URL.

3. **[architecture]** Новая `.onContinueUserActivity(NSUserActivityTypeBrowsingWeb)` использует статический `DeepLinkRouter.handle` (через `.shared` shim), хотя `RecipeScalerNativeApp` держит настоящий `@State container: AppContainer`. Согласно AGENTS.md Composition Root, `.shared` — shim только для AppIntents/pre-bootstrap; здесь composition root имеет прямой доступ к инстансу.
   - Impact: shim fallback на `Standalone` глушит реальную ошибку — если UL прилетит в окне между `AppContainer.init` throw и смертью процесса, ссылка попадёт в standalone-роутер, который никто не наблюдает.
   - Recommendation: использовать injected instance в новом замыкании (one-line, без регрессий для существующих call sites):

     ```swift
     .onContinueUserActivity(NSUserActivityTypeBrowsingWeb) { [container] activity in
         guard let url = activity.webpageURL else { return }
         if let link = DeepLinkRouter.parse(url) {
             container.deepLinkRouter.handle(link)
         }
     }
     ```

     Это также укрепляет extraction `parse` (finding 5) как правильный инструмент.

4. **[security, auto]** Whitelist хостов — строковое сравнение `recipe-scaler.ru` / `www.recipe-scaler.ru`. Не покрывает IDN/look-alike (`reciре-scaler.ru`).
   - Impact: теоретический. iOS сама не направит чужой URL в `NSUserActivityTypeBrowsingWeb` с нашим `webpageURL`, потому что чужой AASA наш app не заявит. В `.onOpenURL` чужой `https://` может прийти из share-sheet только если юзер осознанно выбрал «открыть в Recipe Scaler».
   - Recommendation: no action для v1.

### Low

5. **[architecture]** `parse(_ url:)` извлечён как `static func` — чистый, без мутации `pending`. Корректный рефакторинг, делает парсер unit-тестируемым (UL cases в `DeepLinkRouterTests` подтверждает).
   - Impact: surface expansion ограничен; единственный smell — `nil` означает и «не deep link», и «valid URL мы намеренно отвергли» — будущий logging «проигнорирован UL на не-заявленном path» придётся вводить с новым типом.
   - Recommendation: accept as-is. Альтернатива (internal `ParsedDeepLink` enum с `.rejected(reason)`) — gold-plating для одного caller-а.

6. **[architecture]** В AASA route (`server/src/routes/apple-app-site-association.ts`) нет комментария, почему `/public/shopping-list/*` и legacy `/public/{uuid}` намеренно исключены.
   - Impact: будущий разработчик может «добросовестно» расширить whitelist, не зная, что для shopping-list нет нативного viewer-а. Спека (`contracts/aasa.md`) фиксирует, но код должен ссылаться.
   - Recommendation: 3-строчный комментарий в `APPLE_APP_SITE_ASSOCIATION`:

     ```ts
     // Deliberately NOT claimed (see specs/059-universal-links/contracts/aasa.md):
     // - /public/{recipeId} (legacy, no @) — stays in Safari
     // - /public/shopping-list/* — guest viewer is out of scope (spec 059 §"Вне scope")
     // - /oauth/*, /#//* — web-only
     ```

7. **[architecture]** Три источника правды для `/public/*` paths: AASA (`apple-app-site-association.ts`), OG routes (`og-public-pages.ts`), nginx config. Сегодня консистентны (AASA — строгое подмножество OG).
   - Impact: drift-сценарии не ловятся тестами. (a) Новый OG route `/public/collections/:id` кто-то думает, что откроет app — нет. (b) AASA расширяют до `/public/*` для удобства → `/public/shopping-list/...` открывает app, но `parseUniversalLink` вернёт `nil` → ссылка молча drop, юзер на дефолтной вкладке. Хуже, чем в Safari.
   - Recommendation: экспортировать path list как именованный const (`PUBLIC_AASA_PATHS`) и unit-test-ом проверять, что он subset OG route prefixes. Не блокирующее для merge 059.

8. **[standards, auto]** `Cache-Control: public, max-age=300` (5 минут) — Apple реально кэширует AASA дольше (~1 сутки после первого fetch). 5-минутный TTL не вредит, но создаёт ложное ощущение быстрой инвалидации.
   - Impact: минимальный. Развёртывание новых paths потребует ~1 суток для всех установленных приложений независимо от нашего `max-age`.
   - Recommendation: повысить до `max-age=86400` (1 сутки) или оставить с комментарием о реальном поведении Apple CDN.

9. **[business-logic, auto]** `parse(_ url:)` — `parts[2].removingPercentEncoding ?? parts[2]`. Если в username было `%2F`, `removingPercentEncoding` раскодирует его в `/`, но к `parts` это уже не вернётся.
   - Impact: теоретический. В реальных usernames (генерируются через `human-id`) слэшей не бывает; серверная валидация должна отбросить.
   - Recommendation: no action для v1.

10. **[business-logic, auto]** Тесты координатора `test_openPublicProfile_switchesToDiscover` / `test_openPublicRecipe_switchesToDiscoverWithStack` проверяют только `selectedTab == .discover` и `discoverPath.isEmpty == false`, не содержимое path.
    - Impact: можно случайно сломать маршрутизацию (положить не тот route) — тесты останутся зелёными.
    - Recommendation: в следующих итерациях извлекать первый элемент `NavigationPath` через тест-хелпер и ассертить значение. Не блокирующее для v1, потому что парсер покрыт отдельно в `DeepLinkRouterTests`.

11. **[business-logic, auto]** Для `/public/@/{username}/{recipeId}` координатор кладёт `profile` **затем** `recipe` — совпадает с паттерном `DiscoverPublicProfileView.swift:77` (profile → recipe), back button работает корректно.
    - Impact: нет. Подтверждено консистентностью с существующим UI-флоу.
    - Recommendation: no action.

## Recommendation

**Approved**. Изменения корректные, хорошо покрыты unit-тестами, AASA — современный корректный формат. Все находки — medium или ниже. Architecture-сабагент подтвердил структурную корректность и подсветил три medium-проблемы (DRY хоста, явная идемпотентность, composition root) — все релевантные, но ни одна не блокирует merge.
