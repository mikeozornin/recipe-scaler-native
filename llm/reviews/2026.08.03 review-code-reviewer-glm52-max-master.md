# Code Review: master (spec 038 per-account reset)

## Summary

Three reviewers ran in parallel: **Business Logic**, **Security**, **Architecture & Standards**. Security returned no findings. Two issues surfaced (one of them flagged independently by two reviewers).

- **State-machine coverage**: complete. All teardown paths (`logout()`, `wipeLocalSession(reason:)`, `deleteAccount(seedPhrase:)`, `AppContainer.stopForLogout()`) reach `FeatureAdoptionStore.clearForLogout()`.
- **Logging boundary**: correct. `RecipeScalerCore` confirmed logging-free; `AccountAPI` is the right place for the new `AppLog` calls.
- **Security**: no PII leakage. Logs use enum raw values, booleans, and `String(describing: type(of: error))` — no userId, token, or seed phrase.
- **Conventions**: naming, pbxproj registration, spec changelog — all consistent.

## Findings (sorted by priority)

### High

1. **[business-logic] Race condition in `markFeatureInstalled` reintroduces the bug class being fixed**
   - **Impact**: The fire-and-forget `Task` in `AuthService.markFeatureInstalled` sets `UserDefaults.standard.set(true, forKey: installedReportedKey)` on POST success with no session-identity check. If the user logs out before the POST round-trip completes, `clearForLogout()` wipes the flag, the in-flight request still completes (server correctly records user A), then the Task writes `true` for the device-global flag. The next account on the same device early-returns at the guard — same symptom as the original bug, reachable through a realistic ~100ms–2s window. `[weak self]` is dead because `AuthService` lives for process lifetime via `AppContainer.shared`.
   - **Recommendation**: capture `SharedAuthStore.userId` at Task entry; before writing the flag, verify the current `SharedAuthStore.userId` still matches. Parity with spec 038 FR-038-N6 watchOS contract. Alternative: namespace the flag per-user (`feature-adoption.installed-reported.<userId>`).

2. **[architecture + business-logic] Regression test fires a real network POST and doesn't actually verify the fix**
   - **Impact**: `testInstalledReportedFlagBlocksSecondCallUntilClearForLogout` only asserts the synchronous local cache flip (`store.report.installedNativeApp`), not that the POST actually dispatches. The test passes regardless of whether the POST is suppressed. Worse, `markFeatureInstalled` calls `AccountAPI.markFeatureAdoption` directly with no injection point, so every test run enqueues a live network POST against `recipe-scaler.ru`. Inconsistent with the established `checkUserExistsProvider` / `exchangeSeedForTokenRecoveryProvider` pattern used elsewhere in `AuthService`.
   - **Recommendation**: introduce an injectable provider closure (e.g. `var markFeatureAdoptionProvider: (FeatureAdoptionClientFeature) async throws -> Void`) and assert call counts in the test. Drop the live network dependency from unit tests.

## Recommendation

**Changes Requested.** Finding #1 is a real correctness regression window that reproduces the exact symptom this fix targets (multi-account device, second account silent). Finding #2 undermines the regression test's value. Both are localized to `AuthService.markFeatureInstalled` and the new test file — fixable without touching the rest of the change.
