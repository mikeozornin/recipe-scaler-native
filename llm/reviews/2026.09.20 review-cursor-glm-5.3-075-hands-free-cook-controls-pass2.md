## Summary

Фикс-коммит сработал по существу: **все 5 блокеров pass 1 закрыты** (blink-окно 100 мс с настоящим state machine; deinit-рантаймы у всех трёх движков; voice fire-gate стал единственным продакшн-путём; matching переписан под поправленный контракт с защитой EN-коллокаций; refresh разрешений по `scenePhase == .active` и безусловный в `onAppear` шита; `AppSheetChrome` навешан). Тесты на фиксы реальные, не вакуозные. Security — чисто: on-device speech теперь принудителен, серверного fallback-пути нет.

Но мерж снова **Changes Requested**: fix-проход внёс/вскрыл **3 новых high**, которые компаундрятся между собой:

1. **Retain cycle контроллера** (`YDocRecipeDetailView.swift:598`) — контроллер → closure → @State-box → контроллер. `deinit`-бэкстоп из фикса **не срабатывает никогда**: камера/микрофон снова могут пережить UI — та самая дыра, которую чинили.
2. **Бесконечный reconfigure-loop** при частичном отказе старта канала (`AwakeScrollController.swift:186-188` + `245-252`) — на устройствах без on-device модели `ru_RU` это вечный stop/start `AVCaptureSession` (мигание зелёной точки, лог-спам).
3. **Restart-churn голоса**: отменённый `recognitionTask` доставляет error в колбэк, guard'ы его пропускают → свежеподнятая здоровая сессия снова tear down/restart — цикл аудио-стека каждые 1–30 с всей вооружённой сессией (батарея/термалы — заявленный бюджет фичи).

Из 21 находки pass 1: **7 FIXED, 4 PARTIAL, 7 NOT FIXED, 3 FIXED-под-поправленный-контракт**.

## Новые находки (сортировка по приоритету)

### High

1. **[arch] Retain cycle: контроллер ↔ `onChannelPrefsChanged` — deinit-бэкстоп мёртв**
   - `YDocRecipeDetailView.swift:598` — `awakeScrollController.onChannelPrefsChanged = pullAwakeChannelBindingsFromStorage`: класс-контроллер держит сильный closure, closure держит копию вью-структуры с `@State`-обёрткой, @State-box держит контроллера. Цикл замкнут, `deinit` `AwakeScrollController` не вызывается никогда.
   - Impact: главный бэкстоп фикса находки 2 (deinit-stop) не срабатывает в продакшне — камера/микрофон снова переживают UI на путях без `onDisappear` (logout-ресет, deep-link). Дополнительно — утечка памяти на каждый заход в кулинарный режим.
   - Recommendation: `[weak self]`-семантика недоступна для struct — роутить через weak-замыкание на контроллер (`onChannelPrefsChanged = { [weak awakeScrollController] in ... }` с выносом pull-логики в контроллер), либо очищать `onChannelPrefsChanged = nil` в `onDisappear`/`deinit` пути. Тест: после симуляции ухода экрана контроллер деаллоцируется (`XCTAssertTrue(deallocated)` через weak-наблюдение).

2. **[logic] Частичный отказ старта канала + безусловный пост-старт ре-синк = бесконечный reconfigure-loop**
   - `AwakeScrollController.swift:245-252` — при отказе одного канала (`voiceStarted == false`, реалистичный случай: нет on-device модели `ru_RU`, `AwakeScrollVoiceEngine.swift:104-109`) commit'ится частичное состояние; `:186-188` — `if channelsRunning { syncArmState() }` видит `runningVoice(false) != wantVoice(true)` → `stop(reason: "reconfigure")` → `startIfNeeded()` немедленно ретраит без backoff (отказ движка ≠ denied — `applyDeniedSnapOff` цикл не разрывает).
   - Impact: вечный stop/start `AVCaptureSession` (мигание зелёной точки), неограниченные `onStartChannels`/`onStopChannels` (thrash баннера), спам AppLog — именно на устройствах без speech-модели.
   - Recommendation: считать отказ старта движка аналогом denied для канала (snap-off префа + `onChannelPrefsChanged`), либо `degradedChannels`-сет, исключаемый из сравнения running-vs-wanted; тест с фейковым отказом voice при живой камере: `channelStartCount` ограничен.

3. **[perf] Отменённый recognitionTask каскадом рестартит здоровый голосовой стек — restart-churn loop**
   - `AwakeScrollVoiceEngine.swift:155-168` — колбэк результата guard'ится только epoch и `onAction != nil`: нет идентичности таска и нет фильтра cancellation-error. `SFSpeechRecognitionTask.cancel()` (через `runtime.tearDown()` `:33`) доставляет error в колбэк; `restartIfCurrent` намеренно сохраняет epoch (`:218-226`) → отменённый таск проходит оба guard'а и `scheduleRestartIfCurrent` (`:204-215`) убивает только что поднятую сессию. Каждый рестарт порождает следующий; 55-секундный rearm сбрасывает `restartDelay` в 1 с (`:173`).
   - Impact: непрерывный цикл полного аудио-стека (новый `AVAudioEngine` + tap + recognizer + `setActive(false/true)`) каждые 1–30 с всей кулинарной сессии — прямая регрессия батареи/термалов; компаундится с незакрытой находкой 21.
   - Recommendation: захватывать таск/монотонный attemptID и игнорировать результаты/ошибки superseded-тасков; явно фильтровать cancellation-domain ошибки до планирования рестарта.

### Medium

4. **[arch] `sheetOverlay`-эвристика в `onDisappear` может пропустить teardown или реармить мёртвый экран**
   - `YDocRecipeDetailView.swift:660-671` — решение «ушёл ли экран» выводится из `probe.host?.window != nil` при открытом help-шите. Потеря window ≠ вечная правда: шит может закрыться после освобождения, «настоящее» исчезновение теряется; обратный ложнопозитив реармит неживой экран.
   - Recommendation: liveness по реальному факту (scene/window identity, presence в навигации) вместо эвристики; минимум — ревалидировать `detailVisible` в `onDismiss` шита.

5. **[logic] spec.md F3.3 противоречит поправленному voice-whitelist (RU fire на первом партиале)**
   - `spec.md:212` — «Partial results не fire; только final (или debounce stable partial ≥ N ms)» vs поправленный `voice-whitelist.md:46-49` — «RU singleton и фразы 2+ слов: fire на первом matching partial» (код следует контракту, `AwakeScrollVoiceClassifier.swift:5-11`). По precedence (spec > contracts) следующий агент «перефиксит» код обратно — flip-flop. Поправка также расширяет приём RU-речи на хвостовые «вверх/вниз/выше/ниже» («руки вверх» → `.up` без 300 мс стабильности), а `spec.md:355` всё ещё называет «ложные "up" из речи на кухне» главным риском, митигируемым «узким whitelist» — риск-постура спеки не отреконсиlena с трейдоффом.
   - Recommendation: одним коммитом отреконсилять F3.3 и строку риск-таблицы с поправленной политикой — либо, если защита от «руки вверх» нужна, ужесточить trailing-singleton список в контракте.

6. **[arch] Voice умирает навсегда после транзиентного аудио-отказа**
   - `AwakeScrollVoiceEngine.swift` — `setActive` throw / `audioEngine.start` throw / `recognizer.isAvailable == false` → `start() == false` без отложенного retry (finding 12 residual): до следующего цикла тумблера voice мёртв при живом UI-статусе.
   - Recommendation: отложенный retry с backoff для транзиентных аудио-ошибок (отдельно от перманентных: on-device отсутствие — без retry, сразу degraded).

7. **[standards] Дубли ID задач T061–T064 в tasks.md; реализованные пункты не отмечены**
   - `specs/075-hands-free-cook-controls/tasks.md:100-103` (unchecked) vs `:215-218` (checked, US0–US2) — блок perf-followup переиспользует занятые ID; код (15/6 fps, fired-only logging) уже реализован.
   - Recommendation: перенумеровать audit-блок (T070+) или слить в исходные ID и проставить `[x]` с указанием evidence.

### Low

8. **[logic] `permission-teardown.md` §Open Settings протух** — требует «mic или camera denied», код/спека включают speech (`AwakeScrollArmFlags.swift:70`). Contract-conformance-тест пометит корректное поведение нарушением. Recommendation: поправить строку контракта на `mic || camera || speech`.

9. **[logic] Нет потолка возраста pending-blink через потерю face tracking** — `AwakeScrollFaceClassifier.swift:78-91`: pending-wink срабатывает на любом более позднем кадре; потеря якорей (лицо вышло из кадра) + ре-аквизиция через секунды → одиночный ложный скролл после движения головой. Recommendation: drop pending при `now - pendingAt > ~0.25 с`; тест: pending в *t*, резюм в *t+2 с* → nil.

10. **[perf] `compactMap` на каждый ARKit anchor-callback до троттл-проверки** — `AwakeScrollCaptureSession.swift:243-244`, ~60 Гц: под термальным троттлом платим аллокацию, чтобы отбросить ~90% колбэков. Recommendation: поднять `faceThrottle.shouldProcess` выше извлечения якоря или `first(where:)` без промежуточного массива.

11. **[standards] Файл ревью-пасса закоммичен в корне репо** вместо конвенции `llm/reviews/<date> <name>.md` (24 предыдущих файла там). Recommendation: перенести оба пасса в `llm/reviews/2026.09.20 ...`.

## Recommendation

**Changes Requested.** Все три новых high — мерж-блокеры, и все три относятся к жизненному циклу движков: retain cycle обнуляет deinit-бэкстоп (камера/микрофон снова переживают UI), reconfigure-loop и restart-churn превращают длинную кухонную сессию в бесконечный цикл старта/останова камерно-аудио стека на части устройств. Чинить одним проходом по жизненному циклу: (1) разорвать cycle и покрыть dealloc-тестом, (2) degraded-семантика для отказавшего канала, (3) фильтр superseded/cancelled recognition-тасков. Medium 4–6 — желательно в тот же проход (спека-контрактный flip-flop поймает следующего агента); остальное — follow-up.
