## Findings (sorted by priority)

### Critical

None.

### High

1. **[business-logic] Release-notes seed suppresses the v1 note for ~100% of App Store upgraders**
   - `RecipeScalerNative/Services/ReleaseNotesStore.swift:58-64` (`seedIfNeeded`), introduced via `c25600e` into build 1.0.10.
   - Spec 077 staged rollout: mechanism ships with an **empty** catalog so the *next* build's first note gets bannered. But `c25600e` added note `version: 1` into 1.0.10 — the same App Store release that first contains the mechanism. Every user coming from ≤ 1.0.9 has **no** `lastViewed` key → seed writes `max = 1` → `showsBanner == false` forever for note v1. Only interim dev/TestFlight builds that ran the empty-catalog binary (key = `0`) ever see the banner.
   - Impact: the "Follow, hands-free cooking, Vkusvill" announcement never banners for real users; reachable only via the Profile archive row.
   - Recommendation: (a) accept v1 as archive-only and ship the next note as `version: 2` (banner will fire for everyone), or (b) replace the 1.0.10 binary if ASC still allows and move the note to 1.0.11. Add a rule to the prepare-ios-release skill: "first note must land in a build *after* the mechanism's first App Store release."

### Medium

2. **[performance] Camera + mic leak on detail-pop while the help sheet is open**
   - `RecipeScalerNative/Views/YDocRecipeDetailView.swift:669-681` — `onDisappear` skips teardown/callback-nil-out/`deactivateScreenAwake()` when `sheetOverlay` is true; the sheet's `onDismiss` re-syncs with `flags.detailVisible` still `true`, so `syncArmState()` keeps AVCaptureSession + audio engine + speech running after the screen is gone. Reachable via `syncService.activeRecipeWasRemoved` → `dismiss()` (`:636-639`) while the sheet is up. The skipped branch also leaves `onChannelPrefsChanged` set (retains the controller/state cycle that `a4752f5` broke).
   - Impact: unattended front camera (green dot) + mic + speech recognizer running indefinitely — severe battery drain; retained `AwakeScrollController`. (One unproven link: SwiftUI's exact sheet-dismiss ordering on pop.)
   - Recommendation: derive `detailVisible` from view presence that survives sheet presentation (e.g. `.task`-lifecycle cancellation), or re-check `probe.host?.window` in the `onDismiss` sync and stop when the host is gone. **The single fix to prioritize from this review.**

3. **[business-logic, pre-existing] Focus traversal through edit rows truncates >2-decimal amounts in the Y.Doc**
   - Edit drafts seed from the *formatted* value (`YDocIngredientsSection.swift:1004-1006`), and `formatScalarNumber` caps at 2 fraction digits (`RecipeScalerNative/Models/YDoc/IngredientData.swift:196-205`); the unchanged-check (`YDocIngredientsSection.swift:683-690`) then treats `"33.333" → "33.33"` as a change and commits the truncated value into the CRDT doc. Predates this range; 7510376 neither introduced nor fixed it.
   - Impact: silent precision loss in the shared YRS document, propagated to web/other devices; nutrition drift. Requires ≥3-decimal amounts (web input, imports, LLM parse) plus focus traversal (toolbar ↑/↓, keyboard Done, field switch).
   - Recommendation: seed edit drafts from the raw stored string, or make the unchanged-check numeric-with-tolerance (`abs(parsed − stored) < 0.005`). Add a regression test with `"33.333"`.

4. **[business-logic] Voice channel dies silently after a failed error-restart; UI keeps showing it armed**
   - `RecipeScalerNative/Services/Cooking/AwakeScrollVoiceEngine.swift:289-297` — `restartIfCurrent` discards the `start(...)` result; on failure `onAction = nil` and nothing retries (the 55 s rearm task was cancelled in `tearDown()`). `AwakeScrollController.runningVoice` stays `true`; `restartVoiceForLocaleChange` / `syncArmState` / scenePhase-active never restart it.
   - Impact: voice chip looks live, "вниз" does nothing, permanently — until the user toggles the channel or re-enters the recipe.
   - Recommendation: on `start(...) == false`, schedule a backoff retry or notify the controller to run the existing `applyEngineStartFailureSnapOff` path.

5. **[performance] No recognition rotation on `isFinal` — deaf window + transient memory accrual**
   - `AwakeScrollVoiceEngine.swift:196-216` — `result.isFinal` feeds only the fire-policy; the tap keeps appending PCM into the finished request until `rotateRecognitionIfCurrent` fires up to 55 s later. A dead `SFSpeechAudioBufferRecognitionRequest` fed at ~48 kHz float32 accrues roughly 180–200 KB/s until rotation (~10 MB over a full window). Frequency of early on-device finals is iOS-version-dependent (flagged speculative).
   - Recommendation: treat `isFinal` as a rotation trigger (call `rotateRecognitionIfCurrent(epoch:)` when final arrives and the error channel is silent).

6. **[performance] Face channel runs ARKit at default ~60 Hz while consuming 30 Hz**
   - `AwakeScrollCaptureSession.swift:143-155` — `ARFaceTrackingConfiguration.frameRate` never set; the thermal handler (`:222-232`) slows only classifiers (to 6 fps), not the ARSession — inconsistent with the hand path which matches device FPS to the sampler (`:182-185`).
   - Impact: TrueDepth devices burn ARSession/CPU on ~60 anchors/s with half (or 10× under thermal) discarded — sustained extra energy during cooking, when thermal pressure is likely.
   - Recommendation: set `config.frameRate = .fps30` if supported across the target OS range (verify the support matrix); consider lowering under `.serious`/`.critical`.

7. **[security] `processTableCookingEnabled` — UserDefaults override wins over the Release "hide" default**
   - `RecipeScalerNative/Utils/FeatureFlags.swift:23-33` — the override lookup runs *before* the `#if DEBUG` branch, so in Release a seeded UserDefaults value (backup edit, jailbroken device, launch tooling) short-circuits the `return false` and exposes the hidden 074 chrome (`ProcessTableCookingPresenter.swift:76`, `RecipeStepsSection.swift:214`, `RecipeDescriptionEditorBlock.swift:62`).
   - Impact: hidden-feature leak in production builds (no data exposure). Sibling `featureAdoptionGuidesEnabled` has the same override-first shape (pre-existing, defaults OFF).
   - Recommendation: move the override lookup inside `#if DEBUG`, or key it off a debug-only defaults suite never consulted in Release. One-line fix; the only action item blocking a clean 1.0.10 (already uploaded — fold into 1.0.11).

8. **[architecture] `DetailScrollViewProbe` window-wide fallback can silently bind scrolling to the wrong `UIScrollView`**
   - `RecipeScalerNative/Views/DetailScrollViewProbe.swift:31-63` — when the superview walk fails, `discover()` falls back to `largestNonWebScroll(in: window)` (whole-window traversal, WebKit filtered by class-name sniffing `name.contains("WK") || name.contains("Web")`). A *wrong* target is silent — `awake_scroll_probe_missing` fires only when nothing is found.
   - Impact: if the probe drifts out of the scroll hierarchy, or a sheet/cover with a larger scroll view is up while armed (the help sheet deliberately keeps `detailVisible = true`), voice/gesture deltas scroll an unrelated view. Hidden coupling to SwiftUI's UIKit hosting; untestable through the current seam.
   - Recommendation: keep the superview walk as the only production path and treat "probe not inside a scroll view" as failure (log + disarm). If the fallback must stay: require exactly one candidate, replace string sniffing with `isKind(of: WKWebView.self)` up the chain, and log the selected target.

9. **[architecture] Awake-scroll teardown on logout/deauth relies on a UI-callback chain — asymmetric with the `f854f10` pattern**
   - `YDocRecipeDetailView.swift:39` — `@State private var awakeScrollController` owns camera/mic/speech/activated `AVAudioSession`, but `AppContainer.stopForLogout()` (`AppContainer.swift:571-607`) never touches it. Hardware stops only because logout pops the detail view → `onDisappear` — exactly the "косвенные цепочки через UI callbacks" shape ASYNC-LIFECYCLE §3 polices. Deinit backstops make it survivable, but release timing is nondeterministic.
   - Recommendation: (a) document the screen-scoped ownership decision next to the declaration + add a regression test that releasing the controller stops engines; or (b) close the gap cheaply — a weak registry/coordinator `stopForLogout()` can call, mirroring `cooking.dismissForLogout()` from this same window. (Note: finding 2 is the concrete reachable leak through this ownership shape.)

10. **[standards] Interpolated UI literal `Text(": \(column.title)")` shipped + phantom catalog key `": %@"`**
    - `RecipeScalerNative/Views/Cooking/ProcessTablePrepStack.swift:12` (introduced `70a06af`). Xcode auto-extracted a key literally named `": %@"` into `Localizable.xcstrings` with no localizations; the `"Prep" + ": "` composition bypasses the strings catalog.
    - Impact: catalog pollution with an untranslatable phantom key; per-locale punctuation conventions hardcoded.
    - Recommendation: replace with a proper keyed format (`recipe.process-table.column-title` = `"Prep: %@"` / `"Подготовка: %@"`), delete the `": %@"` entry.

11. **[standards] `lint-i18n.sh` blind spot: interpolated `Text("… \(…)")` literals are never scanned**
    - `scripts/lint-i18n.sh:43` explicitly allowlists interpolation; the regex only matches fully-quoted static literals — exactly how finding 10 escaped the machine gate.
    - Recommendation: extend the linter to extract the static prefix of interpolated literals and flag when it contains letters/spaces (allow pure-punctuation/empty prefixes).

## Verified clean (highlights)

- **Privacy/security**: speech hard-pinned on-device (`requiresOnDeviceRecognition = true`); frames exist only as in-memory `CVPixelBuffer`s into Vision — zero persistence/transmission; transcripts never logged (only matched chip enums); pasteboard probed metadata-only behind a real user gesture, `https?://`-filtered; the "camera preview" is a static icon; Release stub covers all 40+ `DebugLaunchOptions` consumers across 17 files; deep links accept only a fixed UUID-validated route table; release notes are compile-time literals rendered with `Text(verbatim:)` (no untrusted-input surface); no secrets in range.

- **Fractional-scale fix (7510376)**: no cumulative drift (always recomputes from base), all ratio paths guard div-by-zero/nil/non-finite, stepper math matches web exactly incl. 1.5 half-away-from-zero rounding; the new invariant test genuinely covers the 60-vs-80 distinction; view-mode scaled edits write only UserDefaults — no CRDT corruption from this feature.
- **Async discipline**: exponential backoff 1 s → 30 s cap with epoch resets, `recognitionAttempt` identity guards, non-MainActor `deinit` backstops, throttle before the MainActor hop, `alwaysDiscardsLateVideoFrames`, `[weak self]` observers — satisfies ASYNC-LIFECYCLE §1 as well as anything in the codebase.
- **Composition root**: 074/076/077 stores all constructed in `AppContainer`, environment-injected, torn down in `stopForLogout`; no Services→Views imports; test seams narrow and documented; test/app target membership verified via pbxproj phases.
- **i18n/typography**: `lint-i18n.sh` PASS; 0 keys actually removed in the range (the ~140 `-` lines were Xcode re-serialization); 47 keys added, all en+ru; no new `.font(.system)` on text — everything via `.appBody()`/`.appFootnote()`/`AppTypography`.
