# Спецификация: AirDrop-передача рецепта через кастомный тип файла

**Ветка**: `057-airdrop-recipe-transfer`
**Дата**: 2026-08-02
**Статус**: 🚧 В разработке
**Зависимости**: `029` (account data export/import — формат v1.4), `012` (recipe share), `027` (third-party import pipeline)
**Эталон**: системный AirDrop share sheet iOS, `UIActivityViewController` / `ShareLink`

## Контекст

Сейчас рецептом можно поделиться только **публичной URL-ссылкой** (`RecipeDetailShareButton` → `RecipeShareSheet` → `ShareLink(item: url)`). Это требует, чтобы:

1. Отправитель был онлайн (нужно переключить `isPublic`).
2. Получатель тоже мог открыть ссылку (веб или нативное приложение).
3. Рецепт стал публично доступен (пусть и по непредсказуемой ссылке).

Для сценария «дай рецепт жене/другу рядом, без публикации в облаке» хочется **прямого P2P-обмена файлом**, без сервера и без публичного флага. Системный AirDrop даёт это бесплатно через стандартный share sheet iOS, без новых entitlement-ов и без privacy manifest-вопросов.

**Ключевое проектное решение**: использовать **кастомный UTType** `ru.recipescaler.recipe`, а не стандартные `public.json`/`public.zip-archive`, чтобы:

- iOS ассоциировала файлы рецептов с Recipe Scaler (иконка, «Open in Recipe Scaler»);
- не было шума в «Open in…» для произвольных `.json`/`.zip`;
- файлы не «принадлежали» бы любому приложению, объявившему эти стандартные типы.



## Цель

Пользователь может отправить один рецепт через AirDrop на другое устройство — получатель тапает Accept, и рецепт **сразу** импортируется в Recipe Scaler (без подтверждения или диалогов) и появляется в коллекции.

## Пользовательские сценарии



### US1 — Отправка рецепта через AirDrop (P1)

**Когда** пользователь открывает Share на детали рецепта, **тогда** в системном share sheet есть опция AirDrop, передающая `.recipe` файл (ZIP-архив формата Recipe Scaler v1.4 с JSON + картинкой внутри, если она есть у рецепта).

### US2 — Приём файла рецепта на другом устройстве (P1)

**Когда** файл `.recipe` приходит через AirDrop, **тогда** iOS показывает системный banner с иконкой Recipe Scaler, тап → приложение открывается и **сразу** запускает импорт (без подтверждения через `ImportRecipeSheet`). Пользователь видит только результат: тост «рецепт импортирован» / сообщение об ошибке.

### US3 — AirDrop без интернета на обоих устройствах (P2)

**Когда** отправитель и/или получатель оффлайн, **тогда** передача файла всё равно работает (AirDrop локальный), импорт работает locally; картинка распаковывается из ZIP-архива `.recipe` файла и прикрепляется к импортированному рецепту даже без сети (картинка хранится локально, как и при импорте из других источников на оффлайне).

### US4 — Конфиденциальность (P2)

**Когда** пользователь отправляет рецепт через AirDrop, **тогда** его `isPublic` флаг **не меняется** — рецепт остаётся приватным, получаетатель работает с локальной копией.

### US5 — Молчаливое разрешение дубликатов (P2)

**Когда** импортируемый `.recipe` файл содержит рецепт, который уже есть у получателя (по `name` или по содержимому), **тогда** применяется стандартная логика обработки дубликатов из существующего import pipeline: создаётся новый рецепт (как и при любом другом импорте), дубликат-детекция не блокирует автоимпорт. Иными словами — поведение AirDrop-импорта идентично поведению file-import из Files.app.

## Требования



### FR-001 — Кастомный UTType

Зарегистрировать собственный UTType `ru.recipescaler.recipe`:

- conforms to `public.zip-archive` (внутри файла — ZIP-архив формата Recipe Scaler v1.4: `recipes.json` + опционально `images/<recipeId>/full.webp` + `images/<recipeId>/preview.webp`);
- filename extension: `.recipe`;
- MIME-type: `application/vnd.recipescaler.recipe`;
- описание для системы: «Recipe Scaler recipe».

Расширение `.recipe` выбрано как короткое, интуитивное и не конфликтующее с существующими public-типами. Поскольку тип **всегда** ZIP-архив, UTType conforms к `public.zip-archive` — это позволяет старым версиям Recipe Scaler и любым зип-читалкам открывать файл как обычный ZIP, а также упрощает распаковку картинок на принимающей стороне (уже работает в `NativeRecipeImporter.parseZip`).

### FR-002 — Info.plist основного приложения

Добавить в `RecipeScalerNative/Info.plist`:

- `UTExportedTypeDeclarations` — объявить `ru.recipescaler.recipe` (мы — владельцы типа);
- `CFBundleDocumentTypes` — заявить, что Recipe Scaler открывает файлы этого типа с ролью `Editor` и `LSHandlerRank: Owner`.

Универсальный `public.zip-archive` **не** заявляем как document type — иначе приложение начнёт перехватывать произвольные `.zip` файлы (налоговые отчёты, фотоархивы и т.п.). Поскольку `.recipe` сам по себе ZIP-архив (conforms to `public.zip-archive`), он будет ассоциирован с Recipe Scaler через наш UTType, не через родительский тип.





### FR-003 — Экспорт одного рецепта в файл

Расширить существующий `NativeRecipeExporter` (или добавить thin wrapper `SingleRecipeFileExporter`):

- на вход: один рецепт;
- на выходе: `URL` файла во `temporaryDirectory` с расширением `.recipe` — **всегда ZIP-архив** формата v1.4 (с `recipes.json` внутри; если у рецепта есть картинка — добавляются `images/<recipeId>/full.webp` + `images/<recipeId>/preview.webp`);
- payload полностью совместим с существующим форматом v1.4, никаких структурных изменений;
- имя файла: `{slugified-recipe-name}.recipe`;
- формат переиспользует существующий streaming-path `exportStreaming` (он уже умеет один рецепт).



### FR-004 — UI отправки

В `RecipeDetailShareButton` / `RecipeShareSheet` добавить опцию «Отправить файлом» (или иконку AirDrop, если системный UI позволяет):

- асинхронно собирает рецепт через сервис экспорта;
- показывает `ShareLink(item: fileURL)` — системный share sheet сам подставит AirDrop;
- сохранённая публичная ссылка остаётся как отдельная опция (как сегодня);
- загрузка/экспорт — с лёгким progress indicator, т.к. сбор картинки может занять время.



### FR-005 — Приём входящего файла (прямой импорт)

В `RecipeScalerNativeApp.swift` расширить существующий `.onOpenURL`:

- для URL с `file://` scheme (или `url.isFileURL`) — маршрутизировать в новый `DeepLink.openRecipeFile(URL)`;
- `AppShellCoordinator.handleDeepLink(.openRecipeFile(url))` **сразу запускает импорт** через `NativeExportImportService.importFile(url:isOnline:shouldStop:progress:)` — без открытия `ImportRecipeSheet` и без подтверждения пользователем;
- во время импорта показывается лёгкий in-app прогресс-индикатор (если импорт идёт дольше 500ms);
- по завершении показывается тост:
  - **успех** — pluralized сообщение из существующего ключа `import.success` (как после обычного импорта);
  - **частичный успех** (есть ошибки по части рецептов) — текст с количеством успешно импортированных + ошибки в детальном развороте;
  - **полный провал** — пользовательское сообщение об ошибке (`UserFacingAPIError.message(for:)`);
- после успешного импорта `AppShellCoordinator` переключается на вкладку Recipes и навигирует к импортированному рецепту (через существующий `completeImport` flow с `primaryRecipeId`, который уже умеет это делать для одного импортированного рецепта);
- security-scoped доступ (`startAccessingSecurityScopedResource()`) обрабатывается внутри `NativeExportImportService.importFile` (он уже это делает сегодня).



### FR-006 — Идемпотентность и безопасность

- На стороне получателя работает **существующий** import pipeline; дубликаты **не** детектятся и **не** блокируют автоимпорт — каждый импорт создаёт новый рецепт (поведение идентично ручному file-import из Files.app, см. US5); лимиты (см. `ThirdPartyImportLimits`) действуют;
- Никаких новых сетевых сущностей, приватных ключей, токенов;
- Privacy manifest не требует новых reason-категорий (AirDrop не использует `NSNearbyUsageDescription`).



### FR-007 — Файл не должен ломать older versions (backward compat)

- Поскольку `.recipe` — это ZIP-архив с `recipes.json` внутри в формате v1.4, любая предыдущая версия Recipe Scaler, которая умеет импортировать `.zip` (а это было всегда), сможет его прочитать по содержимому через `NativeFormatDetector` / `NativeRecipeImporter.parseZip`.
- Если у получателя не установлено Recipe Scaler — файл сохраняется в Files.app как обычный ZIP; пользователь может посмотреть содержимое или установить приложение позже и импортировать вручную через `ImportRecipeSheet → File → pick`.
- Старая версия Recipe Scaler без нового UTType в `Info.plist` не откроет файл автоматически по тапу, но сможет импортировать его вручную через `ImportRecipeSheet → File`.



## Критерии успеха

- **SC-001**: Из детали рецепта можно отправить `.recipe` файл через AirDrop, на получателе тап → открывается Recipe Scaler, импорт запускается автоматически, по завершении показан тост «рецепт импортирован» и пользователь переключен к этому рецепту.
- **SC-002**: После успешного импорта рецепт появляется в коллекции получателя; `isPublic` у отправителя не изменился.
- **SC-003**: AirDrop файла от/на устройство без установленного Recipe Scaler → пользователь получает файл в Files.app (не теряется).
- **SC-004**: Произвольный `.json` (например, налоговый отчёт) **не** вызывает предложения «Открыть в Recipe Scaler» (потому что UTType собственный и conforms к `public.zip-archive`).
- **SC-005**: Произвольный `.zip` (например, фотоархив) **не** вызывает предложения «Открыть в Recipe Scaler» (потому что мы не заявляли `public.zip-archive` как document type — только `ru.recipescaler.recipe`).



## Out of scope

- Передача нескольких рецептов или коллекций через AirDrop (будет в отдельной спеке, если попросит).
- Nearby Interaction / NameDrop / UWB — обсуждались, отложены; AirDrop file — базовый путь.
- Веб-экспорт в `.recipe` формат (синхронизация расширения с `recipe-scaler-web`) — отдельная задача на веб.
- SharePlay / GroupActivities — не подходит по сценарию.
