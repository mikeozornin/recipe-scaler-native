# Спецификация: гайды по пунктам «Насколько вы освоили Recipe Scaler»

**Ветка**: `040-feature-adoption-guides`  
**Дата**: 2026-06-28  
**Статус**: 🟡 Черновик (контент на ревью)  
**Зависимости**: `038-feature-adoption-tracker` ✅ (список, `FeatureAdoptionDetailView`, `FeatureAdoptionItem`), `007-app-shell-navigation` (табы, `AppShellCoordinator`), `010-recipe-import`, `015-assistant` / `021-assistant-full`, `020-account-telegram-export`, `012-sharing`, `026-recipe-collections`, `025-share-extension`, `024-shopping-list-completion`  
**Эталон**: `FeatureAdoptionDetailView`, `AccountView`, `AppShellView` (assistant sheet), `TelegramConnectionView`

## Контекст

Раздел feature adoption (spec 038) показывает 9 чек-поинтов с коротким footnote. Footnote даёт намёк, но не объясняет *как* попробовать фичу и *зачем* она нужна. Пользователи не находят Share Extension, MCP, добавление ингредиентов в список покупок, режимы публичного профиля.

**Цель спеки** — сделать 8 из 9 пунктов кликабельными и вести на экран-гайд с текстом, иллюстрациями, опциональным видео и CTA «попробовать сейчас». Пункт `installed_native_app` остаётся некликабельным (уже выполнен по определению).

Контент ниже — **готовый черновик для i18n** (RU + EN). При реализации ключи переносятся в `Localizable.xcstrings` без fallback-строк в Swift.

## Цель

1. Повысить конверсию «увидел чеклист → попробовал фичу».
2. Снизить обращения «не знал, что так можно».
3. Не дублировать длинные инструкции в footnote списка — только на экране гайда.

## Пользовательские сценарии

### US1 — Открытие гайда из списка (P1)

**Когда** пользователь на экране `FeatureAdoptionDetailView` тапает по строке с chevron, **тогда** открывается `FeatureAdoptionGuideView` для соответствующего `FeatureAdoptionItem` (push в том же `NavigationStack`).

### US2 — Некликабельный пункт (P1)

**Когда** пункт `installed_native_app`, **тогда** строка без chevron, без `NavigationLink`, tap не обрабатывается. Footnote остаётся как в 038.

### US3 — CTA «Попробовать» (P1)

**Когда** пользователь внизу гайда нажимает primary CTA, **тогда** выполняется действие из таблицы навигации (§ Навигация CTA) и экран гайда закрывается (pop) или остаётся в стеке — по типу CTA (внутри приложения — pop + switch tab; внешний Safari — остаётся открытым поверх приложения).

### US4 — Выполненный пункт тоже кликабелен (P2)

**Когда** галочка уже стоит, **тогда** гайд всё равно открывается (перечитать, показать другу). CTA меняет подпись на «Открыть …» вместо «Попробовать …» (отдельные i18n-ключи `*.cta` и `*.cta-done`).

### US5 — Офлайн (P2)

**Когда** нет сети, **тогда** гайд открывается полностью (текст + bundled screenshots + bundled video если в бандле). CTA MCP (внешний Safari) остаётся активным — Safari сам обработает офлайн.

### US6 — Листалка примеров ассистента (P1)

**Когда** открыт гайд `sent_assistant_message`, **тогда** блок «Примеры» — горизонтальная галерея из 5 скриншотов (см. § Компонент `GuideExampleCarousel`). Текст примеров живёт в блоке «Как» выше, чтобы карусель оставалась лёгкой.

### US7 — Медиа (P2)

**Когда** у гайда есть видео или скриншоты, **тогда** они показаны между блоками «Зачем» и «Как». Видео — inline `AVPlayer` + кнопка полноэкранного режима; скриншоты — горизонтальный scroll или одна иллюстрация на шаг.

## Архитектура UI

### Экран `FeatureAdoptionGuideView`

Структура сверху вниз (в `ScrollView` или `List` с прозрачными секциями):


| Блок      | Стиль                | Содержимое                                                            |
| --------- | -------------------- | --------------------------------------------------------------------- |
| Статус    | badge                | «Выполнено» / «Ещё не пробовали» — `account.feature-adoption.state.*` |
| Зачем     | `.appBody()`         | 2–4 предложения                                                       |
| Медиа     | custom               | 0…1 video, 0…N screenshots (см. § Медиа-брифы)                        |
| Как       | нумерованный список  | шаги `.appBody()`                                                     |
| Примеры   | carousel             | галерея скриншотов (ассистент, опц. MCP) — без пузырей                |
| CTA       | `.borderedProminent` | одна primary-кнопка (или без кнопки, если CTA = nil)                  |


Navigation title — короткий заголовок пункта (`item.titleKey`), без дублирования display-заголовка в контенте.

### Компонент `GuideExampleCarousel`

Простая листаемая галерея скриншотов (без текстовых пузырей). Используется на гайдах ассистента и MCP; в общем случае — как дополнение к блоку «Как».

**Поведение:**

- `TabView` с `.tabViewStyle(.page(indexDisplayMode: .always))` — стандартные page dots внизу.
- Внутри каждой страницы — только **изображение** (bundled asset), заполнение по ширине с сохранением пропорций, скругление 12 pt.
- Никаких пузырей пользователя/ассистента, никакой длинной подписи на карточке — весь обучающий текст живёт в блоках «Зачем» и «Как» выше, чтобы листалка оставалась лёгкой.
- Свайп влево/вправо; tap на изображение — открыть на весь экран (опционально, P2).
- Под каруселью — одна общая footnote (i18n-ключ `*.carousel-hint`), например «Свайпните, чтобы увидеть больше примеров».

**Доступность:**

- Каждая страница — отдельный `accessibilityElement` с `accessibilityLabel` вида «Пример 2 из 5: [короткое описание скриншота]» (описание — i18n-ключ `*.image.%d.accessibility-label`).
- Page dots — стандартный `PageTabViewStyle` UI, отдельной подписи не требуют.

### Изменения в `FeatureAdoptionRow`

- Для 8 кликабельных пунктов: обернуть в `NavigationLink(value: item)` + chevron trailing.
- `installed_native_app`: без link.

### Модель контента

```swift
struct FeatureAdoptionGuideContent {
    let item: FeatureAdoptionItem
    let hasVideo: Bool
    let videoResourceName: String?      // bundled mp4
    let screenshotAssetNames: [String]  // bundled images, порядок = порядок шагов
    let exampleImages: [GuideExampleImage]? // карусель примеров (assistant / mcp)
    let primaryCTA: GuideCTA?           // nil = без кнопки (used_shopping_list, created_collection, created_recipe)
}

struct GuideExampleImage {
    let assetName: String
    /// Короткое описание для VoiceOver, не показывается визуально.
    let accessibilityLabelKey: LocalizedStringKey
}

enum GuideCTA {
    case openImportTab
    case openShoppingTab
    case openAssistant
    case openProfileTelegram
    case openSafari(URL)
    case openRecipesCollections
    case openProfilePublicSettings
    case openDiscover
}
```

Контент можно захардкодить в Swift enum extension на MVP; remote manifest — вне scope.

| `created_collection`      | —                           | —                   | без CTA                                                                                        |

**Примечание по MCP Safari:** используется **внешний** Safari (`UIApplication.shared.open`), а не `InAppSafariView` — так пользователь может скопировать URL MCP-сервера и сразу переключиться в своего ассистента без возврата в RS. Точный адрес MCP-страницы уточняется у веб-команды (placeholder `https://recipe-scaler.ru/mcp`).


## Требования

### FR-040-N1 — Кликабельность

8 пунктов (все кроме `installed_native_app`) открывают `FeatureAdoptionGuideView`.

### FR-040-N2 — i18n

Префикс ключей: `account.feature-adoption.guide.<feature_key>.*`

Подключи:

- `.why` — зачем
- `.how.%d` — шаги (или `.how.1` … `.how.N`)
- `.cta` / `.cta-done`
- `.carousel-hint` — подпись под каруселью
- `.example.%d.accessibility-label` — короткое описание i-го скриншота карусели для VoiceOver (визуально не показывается)

Существующие `account.feature-adoption.item.*` и `.footnote` **не менять**.

### FR-040-N3 — Медиа в бандле

- Скриншоты: `RecipeScalerNative/Resources/GuideAssets.xcassets` (или `GuideScreenshots/`)
- Видео: `RecipeScalerNative/Resources/GuideVideos/*.mp4`, H.264, без звука или со звуком — по брифу; max ~5 MB на файл
- Имена ассетов: `guide_<feature>_<nn>` / `guide_<feature>_video`

### FR-040-N4 — Логирование (DEBUG, опционально P2)

`AppLog.info(.ui, "feature_adoption_guide_opened", data: ["item": item.rawValue])`  
`AppLog.info(.ui, "feature_adoption_guide_cta", data: ["item": ..., "cta": ...])`

### FR-040-N5 — Без backend

Новых API не требуется.
