# Спецификация: watchOS — уведомление об окончании таймера + настройка

**Feature Branch**: `062-watch-timer-expiry-notify`

**Дата**: 2026-08-11

**Статус**: Draft

**Input**: User description: «Давай сделаем haptic + вибрация при окончании. Заодно предложи, какие сеттинги можно было бы вынести в Settings (вернём кнопку).»

## Контекст и текущее состояние

Часы (`RecipeScalerNativeWatch`, spec [039-watchos-timers](../039-watchos-timers/spec.md)) уже умеют играть haptic при окончании таймера в **foreground**: `WatchHaptics.timerExpired()` (3× `.notification` с интервалом 0.5 с) вызывается из `TimerListViewModel.checkForExpirations()` во время polling-цикла (каждые 15 с, `foregroundRefreshLoop`).

Что не покрыто на сегодняшний день:

- Если приложение закрыто или экран погашен — haptic не проигрывается вообще. Нет локальной запланированной нотификации на `endDate` таймера.
- Нет UI настройки, позволяющей включить/выключить такое поведение.
- Кнопка Settings на часах была временно закомментирована (нет содержимого). Эта спецификация возвращает её и наполняет единственным переключателем.

Цель спеки — добавить **локальную запланированную нотификацию** на момент окончания активного таймера (haptic, без звука), которая срабатывает даже когда приложение не открыто, и **переключатель** в настройках часов, который этим управляет. Звук намеренно **не** добавляется.

## Пользовательские сценарии & тестирование *(обязательно)*

### User Story 1 — Фоновое уведомление при окончании таймера (Priority: P1)

Пользователь запустил таймер с iPhone или с веба и закрыл watch app (или погасил экран). Когда время таймера истекает, часы вибрируют и показывают карточку уведомления с названием таймера. Открыв уведомление, пользователь попадает в watch app на список активных таймеров.

**Почему этот приоритет**: Главная ценность всей спеки — сегодня пользователь не получает никакого сигнала с часов, если app не открыто. Это базовый сценарий для кухонного таймера.

**Independent Test**: Завести таймер на 30 с через iPhone/web, закрыть watch app, положить руку вниз. Через ~30 с часы вибрируют и показывают карточку.

**Acceptance Scenarios**:

1. **Given** активный непаузнутый таймер с `endDate` через 30 с, **And** watch app закрыт (но устройство включено), **When** наступает `endDate`, **Then** часы выдают haptic-паттерн (3× `.notification`) и показывают карточку локального уведомления.
2. **Given** несколько активных таймеров с разным `endDate`, **When** наступает `endDate` каждого, **Then** пользователь получает отдельное уведомление на каждый таймер, идентифицируемое по названию.
3. **Given** пользователь поставил таймер на паузу с любого устройства после того, как локальная нотификация уже запланирована, **When** пауза зафиксирована в watch app при следующем sync, **Then** запланированная нотификация для этого таймера отменяется и не срабатывает.
4. **Given** пользователь удалил таймер с любого устройства, **When** удаление зафиксировано в watch app, **Then** запланированная нотификация для этого таймера отменяется.
5. **Given** таймер завершается, пока watch app открыт на экране списка, **When** `checkForExpirations` фиксирует окончание, **Then** существующий foreground haptic срабатывает, **And** отдельная локальная нотификация **не** показывается (дублирование не нужно).
6. **Given** уведомление пришло, **When** пользователь тапает по нему, **Then** открывается watch app на экране списка таймеров (не глубокий линк на конкретный рецепт — v2).

### User Story 2 — Настройка «Haptics при окончании» в Settings (Priority: P1)

В watch app на экране списка таймеров (и в Empty/Error/NotAuthorized состояниях) внизу снова появляется кнопка Settings. При тапе открывается экран с единственным переключателем — «Haptics при окончании таймера» — по умолчанию включён. Состояние сохраняется между запусками.

**Почему этот приоритет**: Пользователь должен иметь возможность отключить вибрацию в тихой среде. Без этого P1-уведомления могут раздражать.

**Independent Test**: Открыть watch app → Settings → выключить тумблер → закрыть app → завершить таймер → убедиться, что вибрации/карточки нет.

**Acceptance Scenarios**:

1. **Given** watch app на списке таймеров, **When** пользователь листает вниз, **Then** он видит кнопку Settings (та, что была закомментирована).
2. **Given** кнопка Settings видна, **When** пользователь тапает, **Then** открывается экран с заголовком и одним переключателем «Haptics при окончании».
3. **Given** переключатель в положении ON, **When** пользователь переключает в OFF, **Then** состояние сохраняется немедленно и переживает перезапуск app.
4. **Given** переключатель в OFF, **When** таймер заканчивается (foreground или background), **Then** не проигрывается ни haptic, ни локальная нотификация.
5. **Given** Settings открыт с Empty/Error/NotAuthorized состоянием списка, **When** пользователь тапает Settings там, **Then** открывается тот же экран настройки (состояние Settings не зависит от состояния списка).

### User Story 3 — Гибридная модель: серверный push как fallback (Priority: P2)

Если серверный push `timer_completed` (см. spec [058-live-activity-push](../058-live-activity-push/spec.md)) приходит на watch раньше, чем локально запланированная нотификация, локальная нотификация отменяется и не дублируется.

**Почему этот приоритет**: Защита от двойного срабатывания (локальная + серверная). Без неё пользователь получит две вибрации на один таймер.

**Independent Test**: Иметь рабочий серверный push для watch (зависит от готовности бэкенда), завершить таймер — должна прийти ровно одна вибрация/карточка.

**Acceptance Scenarios**:

1. **Given** локальная нотификация на `endDate` запланирована, **And** сервер прислал `timer_completed` push на watch за 2 с до `endDate`, **When** push обработан, **Then** локальная нотификация отменяется, и пользователь получает только серверное уведомление.
2. **Given** APNs push для watch не зарегистрирован или не доставлен, **When** наступает `endDate`, **Then** локальная нотификация срабатывает как обычно (fallback работает).
3. **Given** серверный push пришёл, когда watch app в foreground, **When** push обработан, **Then** foreground haptic играется ровно один раз (без дублирования с локальной нотификацией).

### Edge Cases

- **Таймер истекает «в прошлом»** (запланированная нотификация на `endDate`, который уже прошёл): iOS немедленно показывает её. На часах это означает, что при sync может прилететь уже закончившийся таймер — нужно не плодить пачку немедленных нотификаций (см. FR-007).
- **Несколько таймеров заканчиваются одновременно**: каждая карточка отдельно, но не более N одновременных (оговорить N = 3 в плане).
- **Logout на iPhone / `userId` purged**: все запланированные локальные нотификации должны быть отменены, чтобы не приходили «забытые» уведомления.
- **Cold launch с уже истёкшим таймером в списке**: foreground haptic не должен срабатывать при первом `bootstrap()` (он и так не сработает из-за `firedExpirations`, но нужно убедиться, что локальные нотификации на просроченные `endDate` не планируются).
- **Permission denied**: пользователь не дал разрешение на уведомления. На watchOS невозможно запросить повторно — Settings должен показывать, что уведомления отключены системно, и не падать.
- **App переустановлен / данные очищены**: состояние Settings (Toggle) должно иметь разумный дефолт (ON) — не блокировать фичу молча.

## Требования *(обязательно)*

### Functional Requirements

- **FR-001**: Часы MUST запрашивать разрешение на локальные уведомления (`UNUserNotificationCenter.requestAuthorization`, `.alert | .sound | .badge` — без `.sound` в поставляемом контенте, см. FR-004) при первом появлении активного таймера или при первом открытии Settings.
- **FR-002**: Для каждого активного непаузнутого таймера с известным `endDate` в будущем часы MUST планировать локальную `UNCalendarNotificationTrigger` с `identifier = "watch-timer-<timerId>-complete"` и временем срабатывания = `endDate`.
- **FR-003**: Контент уведомления MUST содержать локализованный заголовок с названием таймера и `userInfo["timerId"]`. Звук в контенте отключён (`sound = nil`) — вибрация и так играется системой при показе карточки.
- **FR-004**: При pause/resume/delete таймера (как локально, так и по sync с других устройств) часы MUST обновлять запланированную нотификацию: отменять старую и при необходимости планировать новую с пересчитанным `endDate`.
- **FR-005**: Часы MUST показывать экран Settings с одним переключателем «Haptics при окончании таймера» при тапе на кнопку Settings. Состояние хранится в watch-local `UserDefaults` под фиксированным ключом.
- **FR-006**: Когда переключатель из FR-005 в положении OFF, часы MUST отменить все запланированные локальные нотификации об окончании и MUST не проигрывать foreground haptic при окончании.
- **FR-007**: Часы MUST NOT планировать локальную нотификацию на `endDate` в прошлом или в ближайшие N секунд (порог — `grace` ~5 с, отсчитывая от момента sync). Это покрывает «already expired» таймеры и исключает пачку немедленных уведомлений при холодном старте.
- **FR-008**: Часы MUST NOT показывать локальную нотификацию, если foreground `checkForExpirations` уже зафиксировал окончание того же таймера в текущей foreground-сессии (дедубликация foreground/background).
- **FR-009**: Часы MUST отменять все запланированные локальные нотификации при logout (`WatchCredentialsStore.userId == nil` после purge).
- **FR-010**: При получении серверного push `timer_completed` (если/когда APNs для watch доступен) часы MUST отменить соответствующую локальную нотификацию и не дублировать haptic, если он уже был сыгран.
- **FR-011**: Все пользовательские строки (заголовок/тело уведомления, лейбл Settings, лейбл переключателя, accessibility hint) MUST жить в `RecipeScalerNative/Resources/Localizable.xcstrings` (см. [I18N.md](../../docs/I18N.md)). Запрос разрешения и системные кнопки использовать локализованные системой строки.
- **FR-012**: Кнопка Settings и экран настроек MUST корректно отображаться в light/dark и в трёх размерах watch-экрана (40/41/44/45/46 мм — проверить через `layout.md`/`audit-ui-layout.sh`, см. UI-LAYOUT-FROM-FIGMA).

### Key Entities *(опционально)*

- **WatchExpiryNotificationPrefs** — пользовательская настройка «включены ли haptic/нотификации при окончании». Один bool, персистится в `UserDefaults` на часах.
- **Запланированная нотификация** — `UNNotificationRequest` с `identifier = "watch-timer-<timerId>-complete"`, триггер по `endDate`. Живёт в системе, не в app state; идентификатор детерминирован по `timerId`, что позволяет отменять по `removePendingNotificationRequests(withIdentifiers:)`.

## Success Criteria *(обязательно)*

### Measurable Outcomes

- **SC-001**: Пользователь с запущенным с iPhone/web таймером и **закрытым** watch app получает вибрацию и карточку уведомления в течение 5 секунд после `endDate` в ≥ 95% случаев (на включённых часах).
- **SC-002**: Переключатель «Haptics при окончании» в OFF полностью подавляет и foreground haptic, и background локальную нотификацию — 100% случаев на device QA.
- **SC-003**: После logout на iPhone на часах не остаётся ни одной запланированной локальной нотификации (проверяется через `UNUserNotificationCenter.getPendingNotificationRequests`).
- **SC-004**: Один таймер = максимум одна вибрация/карточка, независимо от того, пришёл ли серверный push или нет.
- **SC-005**: Экран Settings открывается ≤ 200 мс (на Apple Watch Series 9 или новее), без задержки, читаемый в light/dark, доступен через VoiceOver (accessibility label/hint для переключателя).
- **SC-006**: Все новые UI-строки переведены минимум на языки, поддерживаемые остальным watch UI (см. текущий coverage в `Localizable.xcstrings` — обычно en/ru).

## Assumptions

- iOS 17.0+ deployment target актуален и для watch-таргета; `UNUserNotificationCenter` доступен на watchOS 9+ (входит в target).
- Разрешение на уведомления запрашивается один раз; повторный запрос на watchOS не предусмотрен системой — если пользователь отказал, фича тихо не работает, и Settings это отражает.
- Серверный push для watch (`timer_completed` через APNs) на момент написания спеки **не реализован** на бэкенде (см. [058](../058-live-activity-push/spec.md) — там push для Live Activity iPhone). Hybrid-сценарий (User Story 3) реален к тестированию только после готовности серверной части; до тогда локальная нотификация работает как единственный канал. Это не блокирует P1.
- Звук намеренно не добавляется — пользовательское решение из clarification step.
- Фоновое пробуждение по `endDate` через `UNCalendarNotificationTrigger` — единственный надёжный канал на watchOS без расширения `WKExtendedRuntimeSession`; последний не используется (out of scope).
- `WKApplication` = `true` (watch app standalone, уже так) — это позволяет часам напрямую регистрировать `UNUserNotificationCenter`.
- Default значение переключателя — ON (фича работает «из коробки» для новых пользователей).
- Раскладка Settings экрана не требует макета в Figma — простой `List { Section { Toggle } }`, проходит через стандартный `audit-ui-layout.sh`.
