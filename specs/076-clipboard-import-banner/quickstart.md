# Quickstart: 076 clipboard import banner

Ручной прогон на симуляторе или девайсе. Pasteboard нельзя надёжно проверить одним unit-тестом OS.

## Подготовка

1. Debug build, залогиненный пользователь, сеть есть.
2. Симулятор: скопировать в буфер ровно `https://example.com/recipe` (без другого текста).
3. Убить приложение полностью, если проверяете «после выгрузки».

## Показ

1. Открыть Recipe Scaler (любой таб).
2. **Ожидание:** снизу плашка, текст про ссылку в буфере, справа «Импортировать». Самой ссылки нет. Табы видны.
3. **Ожидание:** системное «вставлено из …» допустимо; в нашем UI URL нет.

## Импорт

1. Тап «Импортировать».
2. **Ожидание:** Import sheet, текстовый режим, в поле эта ссылка, импорт **уже идёт** (Progress / существующий submit).
3. Дождаться успеха.
4. **Ожидание:** карточка рецепта или список, как 010; зелёный тост; баннер буфера больше нет.
5. Background → foreground с той же ссылкой в буфере: баннера нет (consumed).

## Свайп

1. Снова положить в буфер **другую** чистую https-ссылку (или перезапустить процесс с первой).
2. Показать баннер → свайп вниз.
3. Home → вернуться: баннера нет.
4. Terminate app → открыть с той же ссылкой: баннер снова.

## Негатив

1. Буфер: абзац рецепта или «посмотри https://example.com». **Ожидание:** нет баннера.
2. Copy share-ссылки рецепта / списка покупок из приложения. **Ожидание:** нет баннера.
3. Офлайн (Text в Import недоступен). **Ожидание:** нет баннера.
4. Открыть вкладку Import вручную при URL в буфере. **Ожидание:** баннер не поверх sheet.

## Регрессии

- Share Extension по-прежнему открывает импортированный рецепт; на входе баннер не перебивает.
- Ручной Import tab без seed: пустое поле, без автосабмита.
- `lint-i18n.sh` зелёный; смена языка в Профиле обновляет текст плашки.
