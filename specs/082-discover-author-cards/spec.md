# Feature Specification: Подборки — карточки авторов «Обложка»

**Feature Branch**: `082-discover-author-cards`

**Created**: 2026-10-16

**Status**: Draft

**Input**: идея из `specs/081-ipad-adaptation/spec.md` («Идеи на потом»), выбрана по HTML-прототипу
[prototype.html](prototype.html), вариант «Обложка». В прототипе тап по фото ведёт в рецепт — это решение отменено, см. Clarifications.

**Backend**: контракт API — `recipe-scaler-web/specs/082-discover-author-cards/spec.md`.

## Clarifications

### Session 2026-10-16

- Q: Какой вид карточки? → A: «Обложка»: коллаж фото рецептов сверху, человек под ним.
  Отклонены: «Карточка» (сначала человек, ряд превью), «Полка» (лента рецептов вбок), сетка 5 × 2 как в
  OG-картинке профиля (у большинства авторов 1–3 фото — сетка пустует).
- Q: Нужно ли поле «о себе»? → A: Нет. Данные как сейчас: имя, аватар (если загружен), названия рецептов,
  которые склеивает сервер, и счётчик.
- Q: Откуда фото для коллажа? → A: Новое поле `preview_recipes` в профилях `GET /api/discover/collections`
  (до трёх последних рецептов с фото, видимых по share_mode). Отдельные запросы `/api/users/public/{username}`
  на каждую карточку не делаем.
- Q: Куда ведёт тап по фото? → A: Карточка — одна область нажатия, как в ленте и подборках: тап в любом месте, включая фото, открывает страницу автора.
- Q: Сколько колонок у подборок рецептов на iPad? → A: Две в книжной ориентации, три в альбомной.
- Q: Что меняется на странице автора? → A: Ничего. `DiscoverRecipeCardGrid` уже даёт одну колонку на iPhone
  и колонки от 280 pt на iPad (две в книжной, три в альбомной) — так и просили в ревью прототипа.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Видно, что готовит автор (Priority: P1)

Пользователь открывает «Подборки» и в разделе авторов сразу видит фото их рецептов, а не только имя и
список названий. Так проще выбрать, к кому зайти.

**Why this priority**: ради этого фича; без коллажа карточка не отличается от текущей строки.

**Independent Test**: сервер отдаёт `preview_recipes`; на iPhone в «Подборках» у автора с тремя фото видна
обложка из трёх фото, имя, названия рецептов и счётчик.

**Acceptance Scenarios**:

1. **Если** у автора 3+ рецепта с фото, **Когда** открываю «Подборки», **Тогда** сверху карточки коллаж 16 : 9
   из трёх последних: слева одно большое (2/3 ширины), справа два друг над другом.
2. **Если** у автора 2 рецепта с фото, **Тогда** коллаж из двух фото пополам.
3. **Если** 1 рецепт с фото, **Тогда** одно фото на весь коллаж.
4. **Если** у автора нет рецептов с фото, **Тогда** на месте коллажа заглушка той же высоты (иконка на
   заливке), чтобы карточки в сетке были одной высоты.
5. **Если** аватар загружен, **Тогда** он 52 pt, скруглённый квадрат, наезжает на нижний край коллажа на
   половину высоты, с обводкой цвета фона карточки. **Если** нет — заглушка `person.fill`, как сейчас.
6. Под аватаром: имя (одна строка, обрезка с многоточием; если имени нет — `@username`), под ним `description`
   (до двух строк), ниже счётчик «N рецептов» (`discover.profile.recipe-count`).
7. **Если** сервер ещё не отдаёт `preview_recipes` (старая версия), **Тогда** карточка показывается с
   заглушкой вместо коллажа, без ошибки загрузки «Подборок».

---

### User Story 2 — Тап по карточке открывает автора (Priority: P1)

**Why this priority**: карточки в ленте и подборках нажимаются целиком; карточка автора ведёт себя так же.

**Independent Test**: тап по фото первой карточки открывает страницу автора; «назад» возвращает в «Подборки»
на ту же позицию прокрутки.

**Acceptance Scenarios**:

1. **Когда** тапаю в любом месте карточки — фото, аватар, имя, подпись, счётчик или заглушку, **Тогда**
   открывается `DiscoverPublicProfileView` автора, как сейчас.
2. Нажатая карточка подсвечивается целиком, как карточки подборок.

---

### User Story 3 — Сетка на iPad (Priority: P2)

**Acceptance Scenarios**:

1. **Если** iPad в режиме `.padRegular`, **Тогда** страница «Подборки» шириной до 1100 (было 720), карточки
   авторов в сетке с колонками от 260 pt и промежутком 18: три колонки в альбомной, две в книжной.
2. **Если** `.padRegular`, **Тогда** карточки подборок рецептов (раздел выше авторов) в сетке: две колонки в
   книжной ориентации, три в альбомной — чтобы на ширине 1100 строки не растягивались.
3. **Если** iPhone или iPad в узком окне (Split View / Slide Over, `.padCompact`), **Тогда** одна колонка на
   всю ширину, как на iPhone.
4. Поворот iPad и смена ширины окна перестраивают сетку без прыжка прокрутки к началу.

---

### Edge Cases

- Очень длинное имя («Константин Верещагин-Абрамовский») — одна строка с многоточием, высота карточки не
  меняется.
- Автор со 128 рецептами, из которых с фото один, — одно фото на весь коллаж, счётчик «128 рецептов».
- Фото не загрузилось (сеть, 404) — плитка остаётся заливкой с иконкой, соседние плитки не сдвигаются.
- Тёмная тема — обводка аватара и заливки заглушек из системных цветов.
- Dynamic Type до AX3: подпись остаётся в две строки, имя в одну; карточка растёт по высоте, коллаж нет.
- VoiceOver: карточка — одна кнопка «{имя}, {N рецептов}», ведёт на автора; фото декоративные.
- Много авторов (сервер отдаёт без лимита) — сетка ленивая (`LazyVGrid` / `LazyVStack`), фото грузятся при
  появлении.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `PublicProfilePreviewDTO` декодирует `preview_recipes` — массив `{ id, name, image_url }`;
  отсутствие ключа = пустой массив (совместимость со старым сервером).
- **FR-002**: коллаж показывает первые до трёх элементов `preview_recipes` в порядке ответа сервера
  (новые первыми); раскладка по числу фото — US1 сценарии 1–4.
- **FR-003**: URL фото строится из `image_url` ответа (относительный → `Config.baseURL`), как
  `DiscoverAPI.avatarURL(fromPublicProfile:)`. Размер и версия уже в URL от сервера (`size=card`, 640 px;
  `preview=true` — 128 px, для коллажа мало).
- **FR-004**: фото грузятся через существующий кэш публичных картинок (`DiscoverImageLoader` →
  `PublicImageCacheService`), не через `AsyncImage`.
- **FR-005**: вся карточка — одна кнопка → `DiscoverRoute.profile(username)`; отдельных целей нажатия на фото нет.
- **FR-006**: аватар — `DiscoverAvatar` 52 pt по `DiscoverImageURLs.avatar(username:)`, как сейчас.
- **FR-007**: на `.padRegular` — ширина страницы 1100, сетка авторов `adaptive(minimum: 260)`, промежуток 18;
  подборки рецептов — две колонки в книжной, три в альбомной. Иначе одна колонка.
- **FR-008**: строка автора `DiscoverRootPreviewCard` для профилей заменяется новой карточкой; карточки
  подборок рецептов остаются прежними (меняется только их раскладка на iPad).
- **FR-009**: accessibility identifiers: карточка `discover.author-card.{username}`, фото
  `discover.author-card.{username}.photo.{index}`.
- **FR-010**: поиск и «Моя лента» не меняются.

### Key Entities

- **PublicProfilePreviewDTO** (+`previewRecipes: [DiscoverPreviewRecipeDTO]`).
- **DiscoverPreviewRecipeDTO**: `id: String`, `name: String`, `imageUrl: String` (`id` — ключ элемента в `ForEach`, для перехода не используется).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: на iPhone и iPad (обе ориентации) карточки авторов совпадают с прототипом «Обложка» по
  раскладке коллажа, положению аватара, числу колонок.
- **SC-002**: «Подборки» открываются с одним запросом `/api/discover/collections` — без запроса на каждого
  автора.
- **SC-003**: со старым сервером (без `preview_recipes`) экран открывается без ошибки, все карточки с
  заглушкой.
- **SC-004**: тап в любом месте карточки, включая фото, открывает страницу автора (UI-тест).

## Verification

- Unit: декодирование `PublicProfilePreviewDTO` с `preview_recipes`, без ключа, с пустым массивом; выбор
  раскладки коллажа по числу фото (0–3+).
- UI (`DiscoverPublicSpec`): карточка автора с фото видна; тап по фото и по имени → страница автора.
- iPad: кадры «Подборок» в альбомной и книжной для ревью глазами (`docs/AGENT-WORKFLOW.md`, раздел iPad).
- Ручная проверка тёмной темы, Dynamic Type AX3, VoiceOver.

## Assumptions

- Бэкенд выкатывается раньше или вместе с приложением; приложение работает и со старым сервером (FR-001).
- Порядок «новые первыми» — по `recipes.created_at`, как у картинки превью профиля в OpenGraph.
- Web-клиент показывает такую же карточку «Обложка» (web-спека 082, раздел «Web UI»).

## Границы

**В scope**: карточка автора в «Подборках» (iPhone и iPad), сетка на iPad, раскладка подборок рецептов на
iPad (две колонки в книжной, три в альбомной), поле `preview_recipes` в API (web-спека 082).

**Вне scope**:
- поле «о себе» и редактирование публичного профиля;
- страница автора (уже одна колонка на iPhone и 2–3 на iPad);
- исправление расхождения счётчиков в OpenGraph (`is_public` против share_mode) и заголовков страницы
  профиля — отдельно, в web.
