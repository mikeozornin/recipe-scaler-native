# Закрыть чат в recipe-scaler-native

Вызов этого skill **и есть** просьба пользователя смёржить: закоммитить, обновить ветку от `master`,
смёржить в `master` и убрать всё, что создал чат. Не спрашивай, мёржить ли, — делай; останавливайся
и спрашивай, только где ниже так сказано.

С репозиторием работают несколько чатов (см. `AGENTS.md`, «Параллельная работа»). Закрытие трогает
только то, что сделал этот чат.

## 1. Инвентаризация

Пройди по переписке и составь список:

- файлы, которые чат правил или создал, и в какой папке (основная копия `recipe-scaler-native/` или
  `recipe-scaler-native-wt/<name>/`);
- worktree, ветки `feature/<name>` и симуляторы `RS-<name>` / `RS-<name>-ipad`, созданные чатом;
- другие симуляторы, на которые чат ставил сборку (общие, пара iPhone + Watch и т.п.);
- временные файлы: скриншоты (`/tmp/*.png`, `tmp/`, `.verify-screenshots/`), логи и дампы
  (`.debug-session.ndjson`, `.test-fast.log`), черновые скрипты;
- временное логирование в коде (лишние `print` / `AppLog` / `AgentSyncDebugLog`, отладочные флаги) —
  в отличие от логов, которые фича оставляет намеренно.

Затем проверь реальное состояние: `bash scripts/wt.sh ls`, `git status --short` в каждой затронутой
папке. Всё, чего нет в списке, — чужое, не трогай.

## 2. Коммит

Перед коммитом убери временное логирование.

**В worktree задачи:** закоммить всю работу чата в `feature/<name>`.

**В основной копии:** там часто лежат незакоммиченные правки владельца. Индексируй только правки чата:

- файлы, которые менял только чат: `git add <file>`;
- свои hunks в файле с чужими правками: собери патч только из них и `git apply --cached <patch>`
  (без интерактивного `git add -p`);
- правка в неотслеживаемом файле или зависящая от незакоммиченной работы владельца — не коммить:
  коммит с половиной чужого изменения не соберётся. Оставь в рабочем дереве и скажи об этом.

Перед коммитом проверь `git diff --cached --stat` и `git diff --cached`. Новые Swift-файлы должны
быть в `project.pbxproj` (сборка это покажет).

Стиль сообщения — как в `git log`: `type(scope): тема` до ~70 символов, пустая строка, тело о том,
что изменилось и зачем. Один коммит — одно логическое изменение.

## 3. Догнать master и смёржить

Для каждого worktree:

1. Догони `master` (он обычно ушёл вперёд): в worktree `git rebase master`. Конфликты решай,
   сохраняя смысл обеих сторон; `project.pbxproj` сводится руками, оба набора файлов должны остаться.
   Если конфликт не решить без догадок о намерениях владельца — остановись и спроси.
2. Если `master` принёс новые коммиты — пересобери (`bash scripts/wt.sh run` или build из
   `docs/AGENT-WORKFLOW.md`) и убедись, что всё компилируется.
3. Мёрж из основной копии: `git -C <основная копия> merge --ff-only feature/<name>`. Основная копия
   должна быть на `master`. Если мёрж отказывает из-за пересечения с незакоммиченными файлами
   владельца — остановись и скажи пользователю; никогда не делай stash, reset и не перезаписывай его
   работу.
4. `git log --oneline master..feature/<name>` теперь пуст.

## 4. Уборка

Для каждого worktree, созданного чатом:

1. `git -C <worktree> status --short` пуст — всё оставшееся либо закоммичено на шаге 2, либо
   временный файл на удаление.
2. Из основной копии: `bash scripts/wt.sh rm <name>` — удаляет worktree, его DerivedData и
   симуляторы `RS-<name>` и `RS-<name>-ipad`.
3. `git branch -d feature/<name>`.

Затем удали временные файлы чата из шага 1 и забытые им папки в `recipe-scaler-native-wt/`. Если чат
ставил сборку на симулятор, который не создавал, — напиши об этом в отчёте, не стирай его.

Никогда не удаляй чужие worktree, ветки и симуляторы, симуляторы пользователя и файлы, которые чат
не создавал.

## 5. Отчёт

Коротко пользователю:

- коммиты, теперь в `master`: короткий hash + тема;
- что осталось незакоммиченным и почему;
- удалённые worktree, ветки, симуляторы и временные файлы;
- симуляторы, на которых ещё стоит сборка чата;
- свободное место (`df -h .`).
